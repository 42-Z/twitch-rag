# Implementation Plan: Проверки страницы в настоящем браузере

**Branch**: `004-e2e-browser-tests` | **Date**: 2026-09-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-e2e-browser-tests/spec.md`

## Summary

В проект добавляется Playwright: проверки открывают страницу в настоящем браузере, вводят токен владельца, нажимают кнопки и смотрят на экран. Сервис для проверок поднимается настройкой запуска — своей командой, со своим портом и с подставным окружением, — а сетевые обращения страницы к реестру перехватываются в самих проверках.

## Technical Context

**Language/Version**: TypeScript; Bun 1.4 — сборка, остальные проверки; Playwright 1.63 для браузерных

**Primary Dependencies**: добавлена одна зависимость разработки — `@playwright/test`. В самом сервисе новых зависимостей нет

**Storage**: не затрагивается: проверки работают с заглушками и в боевые хранилища не ходят

**Testing**: `bunx playwright test` (`bun run test:e2e`), браузер chromium скачивается отдельно

**Constraints**: бесплатный тариф и живые сервисы не затрагиваются; проверки идут в настоящем браузере, но без окна

**Scale/Scope**: две проверки: подпись после добавления и поведение кнопки повторного разбора

|---------|---------------------------|--------|
| I. Документация прежде действия | Настройка запуска, перехват сети и запуск браузера — по документации Playwright; проверено запуском | ✅ |
| II. Чистый расширяемый код | Общие значения (адрес, токен, подставные адреса) вынесены в один модуль, настройка и проверки берут их оттуда; проверки не лезут во внутренности страницы | ✅ |
| III. Пользовательский опыт — критерий готовности | Ради этого всё и делается: проверяется, что страница не обещает работу, которой сервис не начал | ✅ |

| VI. Логика дизайна | Текстов на экране не добавляется: проверяются те, что уже есть | ✅ |

**Обоснование новой зависимости** (требование конституции): кнопку в браузере не нажать имеющимся стеком — проверки проекта рисуют разметку без браузера. Зависимость только для разработки, в сборку сервиса не попадает.

## Project Structure

```text
playwright.config.ts          настройка запуска: сборка, поднятие сервиса, подставное окружение
tests/e2e/settings.ts         общие значения: адрес, порт, токен, подставной адрес
tests/e2e/interface-truth.e2e.ts  проверки: подпись после добавления и поведение повторного разбора
```

**Structure Decision**: проверки живут в `tests/e2e` рядом с остальными, но с расширением `.e2e.ts` — иначе `bun test` заберёт их в свой прогон и упадёт на чужом запускающем.

## Решения

### 1. Сервис поднимается настройкой запуска, а не руками

`webServer` в настройке собирает страницу и запускает `wrangler dev` на своём порту. Одна команда — и проверки готовы к работе; ничего поднимать заранее не надо, и забыть поднять тоже нельзя.

### 2. Подставное окружение — не украшение, а защита

Адреса хранилищ у проверочного сервиса ведут в никуда: `--var` перебивает значения из `.env` (проверено: здоровье хранилища при этом отвечает отказом). Если перехват в проверке не сработает, запрос упрётся в отказ, а не запишет что-нибудь в боевой реестр. Страница собирается с подставным адресом реестра по той же причине.

### 3. Сеть перехватывается в проверках

Локальному сервису отдаются только страница и её файлы; обращения к реестру и управляющие запросы отвечаются заглушками. Это позволяет проверять и пропуск, и начало разбора, не заводя для этого записей в бою.

### 4. Расширение `.e2e.ts`, а не `.spec.ts`

`bun test` собирает по проекту всё, что названо тестом, и на файле Playwright падал: их `test()` работает только под своим запускающим. Расширение разводит два набора, а `testMatch` в настройке указывает, что искать.
