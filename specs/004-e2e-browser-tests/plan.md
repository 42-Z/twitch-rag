# Implementation Plan: Проверки страницы в настоящем браузере

**Branch**: `004-e2e-browser-tests` | **Date**: 2026-09-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-e2e-browser-tests/spec.md`

## Summary

В проект добавляется Playwright: проверки открывают страницу в настоящем браузере, вводят токен владельца, нажимают кнопки и смотрят на экран. Сервис для них поднимается так, как это описывает Cloudflare для проверок Worker'а целиком — `createTestHarness()` из `wrangler`, — с подставными секретами вместо боевых; обращения страницы к реестру перехватываются в самих проверках.

## Technical Context

**Language/Version**: TypeScript; Bun 1.4 — сборка и остальные проверки; Playwright 1.63 — браузерные

**Primary Dependencies**: добавлена одна зависимость разработки — `@playwright/test`. Подъём сервиса идёт через `createTestHarness()` из уже установленного `wrangler` — новой зависимости для этого не нужно

**Storage**: не затрагивается: секреты подставные, а обращения страницы к реестру перехвачены

**Testing**: `bunx playwright test` (`bun run test:e2e`); браузер chromium скачивается отдельно, в пакетах его нет

**Constraints**: живые сервисы не затрагиваются; проверки идут в настоящем браузере, но без окна

**Scale/Scope**: три проверки: подставное окружение сервиса, подпись после добавления, поведение кнопки повторного разбора

**Обоснование новой зависимости** (требование конституции): кнопку в браузере не нажать имеющимся стеком — проверки проекта рисуют разметку без браузера. Зависимость только для разработки, в сборку сервиса не попадает.

## Project Structure

```text
playwright.config.ts                 настройка запуска: что искать, как собирать, размер экрана
tests/e2e/settings.ts                подставные значения и токен владельца
tests/e2e/fixtures.ts                подъём сервиса, адрес, сброс состояния
tests/e2e/build.ts                   сборка страницы до проверок
tests/e2e/interface-truth.e2e.ts     проверки
```

**Structure Decision**: проверки живут в `tests/e2e` рядом с остальными, но с расширением `.e2e.ts` — иначе `bun test` заберёт их в свой прогон и упадёт на чужом запускающем.

## Решения

### 1. Сервис поднимается `createTestHarness()`, а не запуском `wrangler dev`

Документация Cloudflare называет для проверок Worker'а целиком именно этот способ: он запускает сборку по её настройке, отдаёт адрес, позволяет читать окружение и сбрасывать состояние между проверками. Своими руками поднимать сервис и угадывать порт не приходится, а проверяется то, что выпускается.

### 2. Значения для проверок подменяются штатно, а не ключами запуска

`vars` и `secrets` задаются при подъёме сервиса — это документированный способ, и он не требует заводить отдельное окружение. Первая версия правки подменяла секреты ключами `wrangler dev --var`; это работало, но было самоделкой, и от неё отказались.

Подставные адреса хранилищ ведут в никуда. Это не украшение: промах мимо заглушки в проверке приводит к отказу, а не к обращению к боевому хранилищу. Отдельная проверка следит за тем, чтобы окружение оставалось подставным (SC-002).

### 3. Сеть перехватывается в проверках

Локальному сервису отдаются только страница и её файлы; обращения к реестру (страница читает его прямо из браузера) и управляющие запросы отвечаются заглушками. Это позволяет проверять и пропуск, и начало разбора, не заводя записей в бою.

### 4. Страница собирается с подставным адресом реестра

Адрес реестра закладывается в страницу при сборке. Проверки собирают её с адресом, ведущим в никуда (`globalSetup`): тогда даже промах мимо перехвата не станет обращением к боевому хранилищу.

### 5. Расширение `.e2e.ts`, а не `.spec.ts`

`bun test` собирает по проекту всё, что названо тестом, и на файле Playwright падал: их `test()` работает только под своим запускающим. Расширение разводит два набора, а `testMatch` в настройке указывает, что искать.
