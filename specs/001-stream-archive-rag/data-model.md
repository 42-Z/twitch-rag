# Модель данных: База знаний канала по записям стримов

**Дата**: 2026-09-13 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

Данные живут в трёх местах, и это разделение — главный инвариант проекта:

| Где | Что хранится | Срок жизни |
|-----|--------------|-----------|
| SQLite (`bun:sqlite`, локальный файл) | состояние канала, трансляций, очереди, журнал событий, лог запросов | постоянно |
| Upstash Vector | документы знаний с эмбеддингами и метаданными | постоянно |
| Upstash Blob | куски аудио на время обработки одной трансляции | минуты–часы, удаляются по завершении |

Расшифровка и медиафайл **не хранятся**: транскрипт живёт в памяти процесса между этапами
транскрипции и структурирования, аудио — в Blob до конца транскрипции. После успешной
индексации от трансляции остаются только запись в SQLite и документы в Vector.

## 1. SQLite: оперативное состояние

### channel

Отслеживаемый канал. Ровно одна активная запись (`is_active = 1`); таблица допускает
несколько строк, чтобы смена канала не требовала миграции.

| Поле | Тип | Правила |
|------|-----|---------|
| `id` | INTEGER PK | |
| `twitch_user_id` | TEXT NOT NULL UNIQUE | id из Helix `Get Users` |
| `login` | TEXT NOT NULL | логин канала, нижний регистр |
| `display_name` | TEXT NOT NULL | |
| `added_at` | TEXT NOT NULL | ISO 8601 UTC |
| `watch_from` | TEXT NOT NULL | граница автообнаружения: VOD с `published_at` раньше неё автоматически не берутся (FR-003) |
| `last_checked_at` | TEXT | момент последнего успешного опроса Helix |
| `last_check_error` | TEXT | причина последней неудачной проверки |
| `is_active` | INTEGER NOT NULL DEFAULT 1 | |

**Правила**: `watch_from` выставляется в момент подключения канала и далее не меняется;
смена канала деактивирует прежнюю запись, документы прежнего канала остаются в Vector до
явного удаления.

### stream

Одна запись эфира (VOD) и её состояние обработки.

| Поле | Тип | Правила |
|------|-----|---------|
| `vod_id` | TEXT PK | id VOD в Twitch |
| `channel_id` | INTEGER NOT NULL → channel.id | |
| `title` | TEXT NOT NULL | |
| `url` | TEXT NOT NULL | адрес записи |
| `published_at` | TEXT NOT NULL | ISO 8601 UTC |
| `published_at_unix` | INTEGER NOT NULL | для фильтров и сортировок |
| `duration_seconds` | INTEGER NOT NULL | из Helix (`1h2m3s` → секунды) |
| `language` | TEXT | определяется при транскрипции, ISO 639-1 |
| `source` | TEXT NOT NULL | `auto` \| `manual` |
| `status` | TEXT NOT NULL | см. состояния ниже |
| `stage_progress` | REAL | 0..1, прогресс активного этапа (FR-029) |
| `attempts` | INTEGER NOT NULL DEFAULT 0 | число запусков обработки |
| `error_code` | TEXT | машинный код последней ошибки |
| `error_message` | TEXT | человеческий текст с подсказкой (FR-030) |
| `document_count` | INTEGER NOT NULL DEFAULT 0 | сколько документов в Vector |
| `speech_seconds` | INTEGER | сколько секунд распознанной речи |
| `cost_usd` | REAL | суммарная стоимость обработки, справочно |
| `created_at` / `updated_at` | TEXT NOT NULL | |

**Состояния** (`status`):

```
discovered → downloading → transcribing → structuring → indexing → ready
     ↓            ↓             ↓              ↓            ↓
   failed ←───────┴─────────────┴──────────────┴────────────┘
ready → deleting → (строка остаётся, document_count = 0, status = deleted)
ready → structuring (переобработка: полный цикл с нуля, FR-033)
```

**Правила**:

- `ready` выставляется только после успешного `upsert` всех документов в Vector.
- Переход в `failed` обязательно заполняет `error_code` и `error_message`.
- При старте приложения любое состояние из середины цикла (`downloading`, `transcribing`,
  `structuring`, `indexing`) считается прерванным и возвращается в `discovered` с
  увеличенным `attempts` (FR-031).
- `attempts >= 3` без успеха переводит трансляцию в `failed` и снимает её с автоповторов;
  ручной перезапуск обнуляет счётчик.

### stream_event

Журнал обработки: источник понятных объяснений оператору и материал для разбора сбоев.

| Поле | Тип | Правила |
|------|-----|---------|
| `id` | INTEGER PK | |
| `vod_id` | TEXT NOT NULL → stream.vod_id | ON DELETE CASCADE |
| `at` | TEXT NOT NULL | ISO 8601 UTC |
| `stage` | TEXT NOT NULL | `discovery` \| `download` \| `transcribe` \| `structure` \| `index` \| `cleanup` |
| `level` | TEXT NOT NULL | `info` \| `warn` \| `error` |
| `message` | TEXT NOT NULL | текст на языке интерфейса, без стек-трейсов |
| `details_json` | TEXT | технические подробности (коды ответов, длительности) |

### media_part

Куски аудио в Blob на время обработки. Существуют только между `downloading` и концом
`transcribing`; строки удаляются вместе с объектами.

| Поле | Тип | Правила |
|------|-----|---------|
| `id` | INTEGER PK | |
| `vod_id` | TEXT NOT NULL → stream.vod_id | ON DELETE CASCADE |
| `part_index` | INTEGER NOT NULL | порядковый номер, с нуля |
| `blob_path` | TEXT NOT NULL | путь в бакете, `audio/{vod_id}/part-{index}.ogg` |
| `offset_seconds` | INTEGER NOT NULL | смещение начала куска в трансляции |
| `duration_seconds` | INTEGER NOT NULL | |
| `bytes` | INTEGER NOT NULL | ≤ лимита загрузки в API транскрипции |
| `state` | TEXT NOT NULL | `uploaded` \| `transcribed` \| `removed` |

**Правила**: `offset_seconds` обязателен — по нему таймкоды куска приводятся к времени
всей трансляции. Пара (`vod_id`, `part_index`) уникальна. Кусок удаляется сразу после
успешной транскрипции, а все оставшиеся — при завершении или отмене обработки.

### query_log

Лог обращений за знаниями: без него невозможно измерить SC-001 и SC-002.

| Поле | Тип | Правила |
|------|-----|---------|
| `id` | INTEGER PK | |
| `at` | TEXT NOT NULL | |
| `client` | TEXT NOT NULL | `http` \| `mcp` \| `operator` |
| `query_text` | TEXT NOT NULL | |
| `top_k` | INTEGER NOT NULL | |
| `filter_json` | TEXT | применённые ограничения |
| `result_count` | INTEGER NOT NULL | 0 означает ответ «знаний нет» (FR-024) |
| `top_score` | REAL | оценка лучшего результата |
| `latency_ms` | INTEGER NOT NULL | |

### setting

Пара ключ–значение для настроек, меняемых без пересборки: расписание опроса, пороги
релевантности, имена моделей, лимит параллельной обработки.

| Поле | Тип |
|------|-----|
| `key` | TEXT PK |
| `value_json` | TEXT NOT NULL |
| `updated_at` | TEXT NOT NULL |

## 2. Upstash Vector: документы знаний

Один вектор = один документ знания. Индекс плотный (DENSE), размерность 1536, метрика
COSINE, пространство имён по умолчанию.

**Идентификатор**: `{vod_id}:{index}` — префикс позволяет удалять и заменять все документы
трансляции одной операцией (`index.delete({ prefix: "{vod_id}:" })`).

**Вектор**: эмбеддинг текста документа, полученный из OpenAI (`text-embedding-3-small`,
1536 измерений).

**data** (неструктурированное поле, возвращается при `includeData`): связный текст
документа — то, что уходит в контекст ИИ-клиента.

**metadata** (JSON, до 48 КБ на вектор, участвует в фильтрах):

| Поле | Тип | Назначение |
|------|-----|-----------|
| `vodId` | string | связь с записью в SQLite |
| `channelLogin` | string | канал (на будущее — фильтр по каналу) |
| `title` | string | название трансляции |
| `publishedAt` | string | ISO 8601 UTC |
| `publishedAtUnix` | number | фильтр по диапазону дат (FR-023) |
| `startSeconds` | number | начало разговора в записи |
| `endSeconds` | number | конец разговора |
| `topic` | string | краткая тема документа |
| `url` | string | ссылка на запись с таймкодом (`...?t=1h2m3s`) |
| `language` | string | язык речи |
| `docIndex` | number | порядковый номер документа в трансляции |
| `confidence` | number | 0..1, уверенность распознавания на этом отрезке |

**Правила и инварианты**:

- Текст документа самодостаточен (FR-014): без местоимений без антецедента и ссылок на
  соседние документы.
- Документ создаётся только по отрезку с распознанной речью; `confidence` ниже порога —
  документ не создаётся (FR-017).
- `startSeconds < endSeconds`, оба в пределах `duration_seconds` трансляции.
- Длина текста — не больше 6000 символов, чтобы вместе с метаданными уложиться в лимит
  48 КБ на вектор и не раздувать контекст клиента.
- Замена документов трансляции атомарна по смыслу: сначала пишутся новые (с новым
  `docIndex`-диапазоном), затем удаляются старые по префиксу, поэтому запрос во время
  переобработки видит либо старый, либо новый набор, но не пустоту (US4, сценарий 3).

## 3. Upstash Blob: временные объекты

| Путь | Содержимое | Когда удаляется |
|------|-----------|-----------------|
| `audio/{vod_id}/part-{index}.ogg` | кусок аудио, моно, пригодный для распознавания | сразу после успешной транскрипции куска |

**Правила**: бакет приватный, доступ только с сервера по токену. При завершении обработки
(успех, ошибка, отмена, удаление трансляции) выполняется `del({ prefix: "audio/{vod_id}/" })`.
Раз в сутки выполняется уборка: объекты старше суток и незавершённые multipart-загрузки
удаляются — они не могут принадлежать активной обработке.

## 4. Промежуточные структуры (в памяти, не хранятся)

| Структура | Поля | Живёт |
|-----------|------|-------|
| `TranscriptSegment` | `start`, `end`, `text`, `confidence`, `noSpeechProb` | от транскрипции до структурирования |
| `Transcript` | `vodId`, `language`, `segments[]`, `durationSeconds` | там же |
| `KnowledgeDraft` | `topic`, `text`, `startSeconds`, `endSeconds`, `confidence` | от структурирования до индексации |

Смещение куска прибавляется к `start`/`end` сегментов сразу после транскрипции, поэтому
дальше по конвейеру время всегда отсчитывается от начала трансляции.
