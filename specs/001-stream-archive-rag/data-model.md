# Модель данных: База знаний канала по записям стримов

**Дата**: 2026-09-14 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

> **Изменено спецификацией [002-document-quality](../002-document-quality/data-model.md)** (2026-09-17):
> у записи канала появилось поле `streamerInfo`, у записи трансляции — `docTitle`; в шапке
> документа и в метаданных куска вместо заголовка с площадки стоит имя документа,
> выработанное по содержанию эфира; разделы снова несут время начала и конца.
> Здесь описан исходный замысел, актуальное состояние — в модели данных 002.

Данные живут в четырёх местах, и это разделение — главный инвариант проекта:

| Где | Что | Срок жизни |
|-----|-----|-----------|
| Cloudflare R2 | куски аудио на время разбора | минуты, удаляются по завершении |
| Upstash Blob | документы трансляций | постоянно |
| Upstash Vector | куски разделов с эмбеддингами | постоянно |
| Upstash Redis | реестр разобранного и пропущенного, настройки | постоянно |

Расшифровка не хранится нигде: она существует только как результат шагов Workflow и
исчезает вместе с завершённым инстансом (FR-010). Аудиофайлы удаляются сразу после
успешного распознавания куска.

## 1. Upstash Redis: реестр и настройки

Читается из двух мест: Worker обращается полным токеном, страница интерфейса — read-only
токеном напрямую из браузера. Поэтому в этой базе не должно быть ничего, что нельзя
показать посетителю страницы.

### `channel` (hash)

Настройка отслеживаемого канала. Одна запись.

| Поле | Тип | Правила |
|------|-----|---------|
| `twitchUserId` | string | идентификатор канала у площадки |
| `login` | string | логин канала, нижний регистр |
| `displayName` | string | отображаемое имя |
| `watchFrom` | number | unix-время подключения; записи старше не берутся автоматически (FR-003) |
| `addedAt` | number | unix-время |
| `lastCheckedAt` | number | момент последнего успешного опроса |
| `lastCheckError` | string | причина последней неудачной проверки |

### `stream:<vodId>` (hash)

Одна запись эфира. Существует и для разобранных, и для пропущенных.

| Поле | Тип | Правила |
|------|-----|---------|
| `vodId` | string | идентификатор записи |
| `status` | string | `processing` \| `ready` \| `skipped` \| `failed` |
| `title` | string | название трансляции |
| `url` | string | адрес записи |
| `publishedAt` | string | ISO 8601 UTC |
| `publishedAtUnix` | number | для сортировки и фильтров |
| `durationSeconds` | number | из метаданных площадки |
| `language` | string | ISO 639-1, определяется при распознавании |
| `categories` | JSON | `[{title, startSeconds, endSeconds}]` — главы записи |
| `sectionCount` | number | число разделов документа |
| `chunkCount` | number | число кусков в векторной базе |
| `speechSeconds` | number | суммарная длительность распознанной речи |
| `docPath` | string | путь к документу в хранилище |
| `source` | string | `auto` \| `manual` |
| `reason` | string | причина пропуска или отказа, человеческим языком |
| `attempts` | number | число попыток разбора |
| `costUsd` | number | стоимость разбора, справочно |
| `processedAt` | number | unix-время завершения |

**Правила**:

- `status = ready` выставляется последним действием разбора, только после того как
  документ сохранён, а куски записаны в векторную базу. Запись в этом состоянии и
  означает «разобрано» — именно по ней Worker решает, брать запись в работу или нет
  (FR-005).
- `status = skipped` с заполненным `reason` ставится для записей, доступных только
  подписчикам, и для удалённых; к таким записям автоматика не возвращается (FR-006).
- `status = failed` — временная неудача; запись берётся снова на следующем опросе, пока
  `attempts` не достигнет трёх, после чего переходит в `skipped` с описанием причины.
- `status = processing` живёт не дольше суток: более старая запись в этом состоянии
  считается брошенной и берётся заново.

### `streams:index` (sorted set)

Элемент — `vodId`, вес — `publishedAtUnix`. Даёт список трансляций по дате одной
командой, без перебора ключей. Используется и страницей, и проверкой «что разбирать».

### `twitch:token` (string с TTL)

Кэш токена доступа к API площадки. Срок жизни ключа берётся из ответа за вычетом запаса;
обновляется по истечении или при отказе авторизации.

**Инвариант**: ключи `stream:*` и `streams:index` всегда меняются вместе — добавление
записи в реестр выполняется одной транзакцией.

## 2. Upstash Blob: документы

| Путь | Содержимое |
|------|-----------|
| `streams/<vodId>.md` | документ трансляции целиком |

Документ — размеченный текст: заголовок с названием, датой и длительностью эфира, затем
разделы. Строка заголовка раздела несёт тему, время начала и категорию:

```
## Причины перехода на новый движок [1:12:30 — 1:18:40 · World of Warcraft]
```

**Правила**: документ пишется один раз, целиком, после успешного составления всех частей.
Это витрина для человека (FR-018, FR-031) и источник для повторной индексации. Бакет
приватный: страница получает содержимое через Worker.

## 3. Upstash Vector: куски разделов

Один вектор — один кусок раздела. Индекс плотный, 1536 измерений, метрика косинуса,
пространство имён по умолчанию.

**Идентификатор**: `<vodId>:<sectionIndex>:<chunkIndex>` — префикс позволяет удалить все
данные трансляции одной операцией при удалении (FR-033).

**Вектор**: эмбеддинг текста куска вместе с дописанным контекстом.

**data**: текст куска, как он ушёл в эмбеддинг — включая контекстную строку.

**metadata** (до 48 КБ на вектор):

| Поле | Тип | Назначение |
|------|-----|-----------|
| `vodId` | string | связь с реестром и документом |
| `title` | string | название трансляции |
| `publishedAt` | string | ISO 8601 UTC |
| `publishedAtUnix` | number | фильтр по диапазону дат (FR-023) |
| `category` | string | категория на момент разговора (FR-014, фильтр) |
| `sectionIndex` | number | номер раздела в документе |
| `sectionTitle` | string | тема раздела |
| `sectionText` | string | **текст раздела целиком** — именно он уходит в ответ (FR-022) |
| `startSeconds` | number | начало раздела в записи |
| `endSeconds` | number | конец раздела |
| `url` | string | ссылка на запись с таймкодом |
| `language` | string | язык речи |

**Правила и инварианты**:

- Текст раздела дублируется в метаданных каждого его куска — это сознательный размен:
  выдача не требует второго обращения к хранилищу. Раздел ограничен шестью тысячами
  знаков, что вместе с остальными полями укладывается в лимит 48 КБ.
- Кусок — полторы–три тысячи знаков. Раздел короче этого попадает в индекс целиком,
  длиннее — режется с перекрытием в двести знаков.
- Контекстная строка в начале куска: дата эфира, категория, тема раздела. Без неё
  кусок, вырванный из документа, теряет привязку (FR-015).
- `startSeconds < endSeconds`, оба в пределах длительности эфира.
- Куски создаются только по разделам с внятной речью (FR-017).

## 4. Cloudflare R2: временные файлы разбора

| Путь | Содержимое | Когда удаляется |
|------|-----------|-----------------|
| `audio/<vodId>/chunk-<NNNN>.m4a` | кусок аудио, AAC 32 kbps моно | сразу после успешного распознавания куска |
| `audio/<vodId>/index.csv` | имена кусков и их смещения во времени | вместе с последним куском |
| `transcript/<vodId>/chunk-<NNNN>.txt` | текст распознанного куска | с концом разбора |
| `transcript/<vodId>/full.txt` | склейка всех кусков — её читают проходы составления | с концом разбора |

**Правила**: при любом завершении разбора — успех, отказ, отмена — выполняется удаление
по префиксам `audio/<vodId>/` и `transcript/<vodId>/`. Ежесуточная уборка удаляет объекты
старше суток: они не могут принадлежать активному разбору, который длится минуты.

**Почему текст распознавания лежит здесь, а не передаётся результатом шага**: результаты
шагов хранятся в состоянии экземпляра Workflow, которое площадка держит три дня после
разбора, а расшифровка не должна переживать разбор (FR-010). Подробности решения —
в [research.md](./research.md), раздел 2.

## 5. Состояние разбора (внутри Workflow)

Не хранится вне инстанса и не переживает его завершения.

| Структура | Поля | Живёт |
|-----------|------|-------|
| Входные данные инстанса | `vodId`, метаданные трансляции, список кусков, главы | весь разбор |
| `ChunkTranscript` | `chunkIndex`, `offsetSeconds`, `segments[{start, end, text, confidence}]` | от распознавания до составления документа |
| `Transcript` | склеенные сегменты всего эфира со сквозным временем | до конца составления |
| `DocumentPart` | текст части документа, границы по времени | до сборки документа |
| `Section` | `title`, `text`, `startSeconds`, `endSeconds`, `category` | до индексации |

Смещение куска прибавляется к меткам сегментов сразу после распознавания, поэтому дальше
по конвейеру время всегда отсчитывается от начала записи.

**Ограничение платформы**: результат одного шага не может превышать мегабайт. Расшифровка
семичасового эфира — около 210 КБ, помещается. Для эфиров вдвое длиннее расшифровка
передаётся между шагами по частям.
