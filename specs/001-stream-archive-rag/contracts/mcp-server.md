# Контракт: MCP-сервер

**Дата**: 2026-09-14 | **Спецификация**: [spec.md](../spec.md) | **HTTP-контракт**: [knowledge-api.md](./knowledge-api.md)

Потребитель знаний — ИИ-ассистент. MCP даёт ему прямой способ пользоваться базой: он
видит инструменты и вызывает их сам, без написания HTTP-клиента.

Сервер живёт в том же Worker, что интерфейс и API, и обслуживает путь `/mcp`. Своей
логики поиска у него нет — он вызывает тот же сервис, что и `POST /api/knowledge/search`.
Расхождение ответов между двумя путями — дефект.

## Транспорт и подключение

**Streamable HTTP без состояния** — единый адрес, каждый вызов самодостаточен. Транспорт
на серверных событиях устарел и не используется. Состояние между вызовами не нужно:
поиск не помнит предыдущих вопросов.

**Авторизации нет** (FR-027): ассистент подключается по одному адресу, без ключей и
регистрации. Инструкция с готовым адресом размещается на странице сервиса (FR-032):

```json
{
  "mcpServers": {
    "twitch-knowledge": {
      "type": "http",
      "url": "https://<адрес-сервиса>/mcp"
    }
  }
}
```

Имя сервера — `twitch-knowledge`, версия берётся из манифеста проекта.

## Инструмент `search_knowledge`

**Описание для модели**: «Найти, что говорилось на стримах канала. Возвращает разделы
пересказов с темой, датой эфира, категорией и ссылкой на момент записи. Использовать,
когда вопрос касается мнений, решений, планов или событий, обсуждавшихся на стримах».

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `query` | string | да | Вопрос или тема обычными словами |
| `topK` | integer | нет | Сколько разделов вернуть, 1–20, по умолчанию 5 |
| `from` / `to` | string | нет | Границы даты эфира, `YYYY-MM-DD` |
| `category` | string | нет | Ограничить категорией трансляции |

**Результат** — текст, готовый к чтению моделью, по блоку на раздел:

```
[1] Причины перехода на новый движок
    «Пятничный разбор кода», 14.03.2026, World of Warcraft, 1:12:30
    https://www.twitch.tv/videos/2345678901?t=1h12m30s

    Полный текст раздела…
```

В `structuredContent` возвращается тот же набор, что отдаёт HTTP API, чтобы клиент мог
разобрать ответ программно.

**Когда знаний нет** — обычный ответ, а не ошибка: «В базе знаний нет сведений по этому
вопросу». Модель должна сказать об этом пользователю, а не додумывать (FR-024).

**Ошибки** возвращаются как `isError: true` с человеческим текстом: недоступность
хранилища, исчерпанная квота, превышение частоты обращений, пустой запрос.

## Инструмент `knowledge_stats`

**Описание для модели**: «Узнать границы базы знаний: какой канал, сколько трансляций
разобрано, за какой период и какие категории встречаются. Использовать, чтобы честно
ответить, есть ли сведения о нужном периоде».

Параметров нет. Возвращает то же, что `GET /api/knowledge/stats`, в человекочитаемом
виде и в `structuredContent`.

## Инструмент `list_streams`

**Описание для модели**: «Перечислить разобранные трансляции с датами и категориями.
Использовать, когда вопрос касается конкретного эфира или периода, а не темы».

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `from` / `to` | string | нет | Границы даты эфира |
| `limit` | integer | нет | 1–50, по умолчанию 20 |

Возвращает идентификатор, название, дату, длительность, категории и число разделов —
данные берутся из реестра, векторный поиск не задействуется.

## Правила

- Инструменты только читают. Запуск разбора, удаление и смена канала недоступны через
  MCP: это операции владельца, они остаются в HTTP API под токеном.
- Описания инструментов пишутся для модели, а не для человека: они определяют, когда
  ассистент обратится к базе.
- Ответ не содержит служебных полей, идентификаторов векторов и отладочных данных —
  только то, что имеет смысл в контексте разговора (FR-025).
- Публичность требует защиты: длина вопроса и число возвращаемых разделов ограничены,
  частота обращений с одного адреса — тоже (FR-028).
