# Implementation Plan: База знаний канала по записям стримов

**Branch**: `001-stream-archive-rag` | **Date**: 2026-09-14 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-stream-archive-rag/spec.md`

## Summary

Сервис следит за одним каналом Twitch, разбирает каждую новую запись эфира и отдаёт
знания ИИ-ассистентам. Распознанная речь превращается в связный документ о трансляции,
разбитый на разделы по темам; разделы попадают в векторный поиск, документ целиком —
в хранилище для чтения человеком.

Основной процесс живёт на Cloudflare: Worker просыпается по расписанию, находит новую
запись и ведёт обработку через Workflow — распознавание, составление документа,
эмбеддинги, сохранение. Вне Cloudflare выполняется только то, что там технически
невозможно: скачивание записи и работа ffmpeg. Этим занимается бокс Upstash, он же
выкладывает готовые куски аудио в R2 и сообщает Worker, что можно начинать.

Весь стек укладывается в бесплатные тарифы без абонентской платы; расход — около
двенадцати центов на семичасовой эфир, из них восемь приходится на распознавание.

## Technical Context

**Language/Version**: TypeScript, Bun 1.4 для сборки и тестов, среда исполнения Worker —
V8-изолят Cloudflare

**Primary Dependencies**: `openai` (официальный SDK, базовый адрес — OpenRouter),
`agents` (MCP-обработчик), `@modelcontextprotocol/sdk`, `@upstash/vector`,
`@upstash/redis`, `@upstash/blob`, `@upstash/box` (запуск прогона), `zod`,
React 19 + Tailwind 4 + shadcn/ui. Внешние программы в боксе: `yt-dlp`, `ffmpeg`

**Storage**: Cloudflare R2 (куски аудио на время разбора) · Upstash Blob (документы) ·
Upstash Vector (разделы, 1536 измерений, косинус) · Upstash Redis (реестр и настройки).
Расшифровка не хранится

**External services**: OpenRouter — `openai/whisper-large-v3-turbo` (распознавание),
`inclusionai/ling-3.0-flash` (документ), `openai/text-embedding-3-small` (эмбеддинги);
Twitch Helix (список записей); Upstash Box (скачивание и нарезка)

**Testing**: `bun test` — модульные тесты чистой логики (разбор длительности Twitch,
склейка таймкодов, разбиение документа на разделы и куски, сопоставление категорий,
сборка фильтров); контрактные тесты Worker через `wrangler dev`; сквозная проверка по
`quickstart.md` на коротком фрагменте записи

**Target Platform**: Cloudflare Workers (бесплатный тариф) + Upstash Box; разработка на
Linux с Bun

**Project Type**: веб-сервис с публичным MCP-интерфейсом и статическим интерфейсом
владельца

**Performance Goals**: ответ на запрос знаний < 1 с (SC-002); четырёхчасовой эфир
доступен как знания в пределах 2 часов (SC-005); запросы обслуживаются во время разбора
(SC-007)

**Constraints**: 10 мс процессорного времени на шаг Workflow и 50 внешних обращений на
вызов (бесплатный тариф); результат шага ≤ 1 МиБ; файл на распознавание ≤ 25 МБ и
60 секунд на запрос у провайдера; выход модели ≤ 32 768 токенов; метаданные вектора
≤ 48 КБ; 5 процессорных часов в месяц у бокса; записи Twitch живут от 7 дней

**Scale/Scope**: один канал, сотни трансляций в год, десятки тысяч разделов, один
владелец, произвольное число публичных клиентов

**Соответствие технологическим ограничениям конституции**:

- **Обращения к моделям идут через официальный SDK OpenAI** — как и предписано. Меняется
  только базовый адрес: запросы уходят на OpenRouter, который совместим с интерфейсом
  OpenAI и для чата, и для распознавания, и для эмбеддингов. Ключи остаются на сервере.
- **Vite не добавляется**, сборка интерфейса остаётся на Bun — соответствует
  ограничению.

- **Среда исполнения соответствует конституции в редакции 1.1.0**: основной процесс в
  Worker без файловой системы и внешних программ, состояние только во внешних
  хранилищах, работа, требующая операционной системы, вынесена в бокс и ограничена тем,
  что в Worker невозможно, долгий процесс оформлен шагами с независимыми повторами.
  Bun остаётся инструментом сборки, тестов и запуска прогона.
- **Расходы**: весь стек укладывается в бесплатные тарифы, фиксированной абонентской
  платы нет; публичные точки доступа ограничены по частоте обращений (FR-028).

**Непокрытых отступлений нет.**

шаблонный код (`src/index.ts`, `src/App.tsx`, `src/APITester.tsx`) заменяется;

сохраняются. Граница между зонами проходит по физической возможности: всё, что требует
внешних программ, — в `pipeline/`, остальное — в `worker/`.

## Инфраструктура и развёртывание

Этапы, которые должны быть выполнены явно.

### И1. Репозиторий

`git init` выполнен, история ведётся. Дальше: выверить `.gitignore` (`.env`, `.box`,
`dist`, `node_modules`), создать репозиторий на GitHub через `gh repo create` и запушить.
Ключей в репозитории нет — они в `.env` локально и в секретах Cloudflare на сервере.

### И2. Внешние сервисы

| Ресурс | Как создаётся | Состояние |
|--------|---------------|-----------|
| Индекс Upstash Vector | `upstash vector create --name twitch-rag --region eu-west-1 --index-type DENSE --dimension-count 1536 --similarity-function COSINE` | **создан**, доступ проверен |
| База Upstash Redis | `upstash redis create --name twitch-rag --region eu-west-1` | создать; нужен и read-only токен для интерфейса |
| Бакет Upstash Blob | `upstash blob create --name twitch-docs --visibility private` | создать |
| Бокс Upstash | `box create --no-repl --runtime node`, затем установка ffmpeg и yt-dlp и `box snapshot` | **создан** (`fun-goshawk-88276`), снимок сделан |
| Бакет R2 | `wrangler r2 bucket create twitch-audio` | создать |
| Приложение Twitch | console.twitch.tv → регистрация приложения | создать |
| Ключ OpenRouter | openrouter.ai | **есть** |

### И3. Конфигурация Cloudflare

`wrangler.jsonc`: привязка бакета R2, привязка Workflow, расписание раз в час, папка
статики `dist`, порядок обслуживания — статика раньше Worker. Секреты через
`wrangler secret put`: ключ OpenRouter, токены Upstash, ключ и секрет приложения Twitch,
ключ API бокса, секрет для приёма сигнала от бокса, токен владельца. Публичные значения
для интерфейса (адрес реестра и read-only токен) попадают в сборку как `BUN_PUBLIC_*`.

### И4. Развёртывание

`bun run build` собирает интерфейс в `dist`, `wrangler deploy` публикует Worker вместе со
статикой и Workflow. Прогон в боксе разворачивается отдельно: код `pipeline/` собирается
в один файл и заливается в бокс, снимок обновляется. Автоматическая публикация из GitHub
через Workers Builds — после того, как ручной путь заработает.

### И5. Первый запуск

Заполнить `.env` → создать недостающие ресурсы (И2) → `wrangler deploy` → открыть
страницу → указать канал → добавить одну запись вручную → дождаться появления документа →
подключить ассистента по инструкции со страницы.

## Complexity Tracking

| Отступление | Зачем | Почему проще нельзя |
|-------------|-------|---------------------|
| Два места исполнения (Cloudflare + бокс) | в изоляте V8 нельзя запустить yt-dlp и ffmpeg, а контейнеры Cloudflare требуют платного тарифа — проверено на аккаунте | без внешнего исполнителя записи не получить вовсе |
| Четыре хранилища | у данных разные роли и сроки: аудио живёт минуты, документы — для человека, разделы — для поиска, реестр — для решений и для страницы | объединение либо ломает бесплатные лимиты (аудио в Blob — половина месячной квоты записей за тридцать эфиров), либо лишает страницу прямого чтения |
| Workflow вместо одного обработчика | сорок кусков на эфир против 50 внешних обращений и 10 мс процессора на вызов | один вызов не проходит по лимитам, а при сбое терялся бы весь эфир |
| Дублирование текста раздела в метаданных кусков | выдача отдаёт раздел целиком без второго обращения к хранилищу | иначе каждый результат поиска требовал бы чтения документа и разбора |
| Полная расшифровка в каждом проходе составления документа | модель обязана видеть эфир целиком, иначе отсылки теряют смысл (FR-013) | нарезка входа дала бы бессвязный пересказ; цена подхода — меньше цента на эфир |
