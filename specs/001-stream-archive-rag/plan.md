# Implementation Plan: База знаний канала по записям стримов

**Branch**: `001-stream-archive-rag` | **Date**: 2026-09-13 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-stream-archive-rag/spec.md`

## Summary

Сервис следит за одним каналом Twitch, забирает аудио каждой новой записи эфира,
распознаёт речь с таймкодами, превращает расшифровку в самодостаточные документы знаний и
складывает их в векторную базу. Потребитель — ИИ-ассистент: он запрашивает знания по
смыслу и получает тексты со ссылками на момент записи. Человеку остаётся интерфейс
настройки, наблюдения за обработкой и проверки качества выдачи.

Технически это один процесс Bun: `Bun.serve()` отдаёт API и операторский интерфейс,
`Bun.cron` раз в 15 минут опрашивает Helix, воркер последовательно проводит трансляцию
через этапы «скачать → распознать → структурировать → проиндексировать», состояние живёт в
SQLite, аудио временно — в Upstash Blob, знания постоянно — в Upstash Vector. Отдельная
тонкая обёртка MCP даёт ассистенту доступ к тому же поиску.

Ключевое ограничение, определившее конвейер: таймкоды возвращает только модель `whisper-1`,
поэтому распознавание идёт через неё кусками по 10 минут, а не через более дешёвую
`gpt-transcribe`.

## Technical Context

**Language/Version**: TypeScript 7 на Bun 1.4 (в системе 1.4.0)

**Primary Dependencies**: `openai` 7.15.0 (распознавание речи, структурирование,
эмбеддинги), `@upstash/vector` 1.2.3 (знания), `@upstash/blob` 0.0.5 (временное аудио),
`@modelcontextprotocol/sdk` 1.30 (подключение к ИИ), React 19 + Tailwind 4 + shadcn/ui
(операторский интерфейс). Внешние процессы: `yt-dlp` 2026.07.04, `ffmpeg` 9.0.1

**Storage**: `bun:sqlite` (состояние, очередь, журнал, лог запросов) + Upstash Vector
(документы знаний, DENSE 1536, COSINE) + Upstash Blob (куски аудио на время обработки).
Расшифровка и медиафайлы не сохраняются

**Testing**: `bun test` — модульные тесты для чистой логики (парсинг длительности Twitch,
склейка таймкодов, нарезка окон, сборка фильтров), контрактные тесты API на поднятом
`Bun.serve()` с подменёнными внешними сервисами, сквозная проверка по `quickstart.md`

**Target Platform**: Linux (EndeavourOS), запуск локально через `bun --hot` и в Docker

**Project Type**: веб-сервис с операторским интерфейсом в одном процессе + MCP-сервер

**Performance Goals**: ответ на запрос знаний < 1 с (SC-002) при нескольких сотнях
трансляций; четырёхчасовой эфир доступен как знания не позднее 2 часов после появления
записи (SC-005); запросы обслуживаются во время обработки без падения скорости более чем
вдвое (SC-007)

**Constraints**: файл для распознавания ≤ 25 МБ; таймкоды только у `whisper-1`; метаданные
вектора ≤ 48 КБ; бесплатный тариф Upstash Vector ограничен размерностью 1536; записи
Twitch живут 7–60 дней — обработка не может откладываться; ключи и токены только на
сервере

**Scale/Scope**: один канал, сотни трансляций в год, десятки тысяч документов, один
оператор, произвольное число программных клиентов в доверенной сети

## Инфраструктура и развёртывание

Этапы, которые должны быть выполнены явно, а не подразумеваться.

### И1. Репозиторий

Проект не под контролем версий (`git` не инициализирован). Порядок: `git init`, выверка
`.gitignore` (`.env`, `data/`, `node_modules`, временные медиафайлы), первый коммит,
создание репозитория на GitHub через `gh repo create` и пуш. Приватность — по решению
владельца; репозиторий содержит только код и документы, ключей в нём нет.

### И2. Внешние сервисы

| Ресурс | Как создаётся | Что попадает в `.env` |
|--------|---------------|----------------------|
| Приложение Twitch | console.twitch.tv → регистрация приложения | `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` |
| Ключ OpenAI | platform.openai.com | `OPENAI_API_KEY` |
| Индекс Upstash Vector | `upstash vector create --name twitch-knowledge --region eu-west-1 --index-type DENSE --dimension-count 1536 --similarity-function COSINE` | `UPSTASH_VECTOR_REST_URL`, `UPSTASH_VECTOR_REST_TOKEN` |
| Бакет Upstash Blob | `upstash blob create --name twitch-audio --visibility private` | `UPSTASH_BLOB_TOKEN` |

Перед созданием ресурсов — `upstash login` (или `UPSTASH_EMAIL` + `UPSTASH_API_KEY`).
`.env.example` содержит все переменные с пояснениями и без значений; `.env` в репозиторий
не попадает. Приложение при старте проверяет наличие каждой переменной и доступность
каждого сервиса, сообщая о проблеме понятным текстом.

### И3. Docker

Образ на базе `oven/bun` с доустановкой `ffmpeg` и `yt-dlp` (версии зафиксированы, yt-dlp
обновляется пересборкой — Twitch меняет выдачу). Том для SQLite и рабочего каталога
временных файлов; переменные окружения из `.env`. `compose.yml` поднимает сервис одной
командой и пробрасывает порт интерфейса. Проверка образа — тот же сценарий, что в
`quickstart.md`, выполненный внутри контейнера.

### И4. Запуск у оператора

`bun install` → заполненный `.env` → `bun dev` (разработка) или `docker compose up -d`
(постоянная работа) → открыть интерфейс, указать канал → добавить одну запись вручную и
дождаться готовности → подключить MCP-сервер к ИИ-ассистенту.

## Complexity Tracking

| Отступление | Зачем | Почему простого варианта недостаточно |
|-------------|-------|---------------------------------------|
| Три хранилища (SQLite + Vector + Blob) вместо одного | у них разные роли и сроки жизни данных: оперативное состояние, постоянные знания, временное аудио | одно хранилище нарушило бы требование «в базе знаний только документы» либо потребовало бы держать состояние очереди в векторной базе, для чего она не предназначена |
| Два интерфейса выдачи знаний (HTTP + MCP) | потребитель — ИИ-ассистент; MCP подключается к нему напрямую, HTTP нужен интерфейсу оператора и произвольным клиентам | только MCP оставил бы операторский интерфейс без API; только HTTP потребовал бы от каждого ассистента собственного клиента |
| Внешние процессы yt-dlp и ffmpeg | официального API для скачивания записей не существует, а перекодирование в 16 kbps сокращает объём в 14 раз | библиотечной альтернативы для Twitch нет; загрузка исходного аудио без перекодирования — 372 МБ на эфир и упор в лимит 25 МБ |
| Дорогая `whisper-1` вместо рекомендованной `gpt-transcribe` | только она возвращает таймкоды | без таймкодов невозможны ссылка на момент записи и SC-003 |
