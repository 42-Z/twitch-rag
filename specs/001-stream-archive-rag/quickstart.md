# Проверка работоспособности

**Дата**: 2026-09-14 | **План**: [plan.md](./plan.md) | **Контракты**: [knowledge-api.md](./contracts/knowledge-api.md), [mcp-server.md](./contracts/mcp-server.md)

Сценарии проверяют, что функция работает, а не только собирается. Порядок важен: каждый
следующий опирается на предыдущий.

## Подготовка

Локально нужны `bun` ≥ 1.4 и авторизованные `wrangler` и `upstash`. Ресурсы создаются
один раз:

```bash
upstash redis create --name twitch-rag --region eu-west-1
upstash blob create --name twitch-docs --visibility private
wrangler r2 bucket create twitch-audio
```

Индекс векторной базы и бокс уже созданы (см. [plan.md](./plan.md), раздел И2). Значения
переносятся в `.env` по образцу `.env.example`; на сервере они устанавливаются как
секреты:

```bash
wrangler secret put OPENROUTER_API_KEY
wrangler secret put UPSTASH_VECTOR_REST_TOKEN
wrangler secret put UPSTASH_REDIS_REST_TOKEN
wrangler secret put UPSTASH_BLOB_TOKEN
wrangler secret put UPSTASH_BOX_API_KEY
wrangler secret put TWITCH_CLIENT_ID
wrangler secret put TWITCH_CLIENT_SECRET
wrangler secret put INGEST_SECRET
wrangler secret put APP_ADMIN_TOKEN
```

Публикация:

```bash
bun install
bun run build          # интерфейс в dist
wrangler deploy        # Worker, Workflow, статика
```

## Проверка 0. Зависимости и доступы

```bash
curl -s https://<адрес>/api/health | jq
```

**Ожидается**: `status: "ok"` и `ok` у каждой проверки — реестр, векторная база,
хранилище документов, R2, OpenRouter, Twitch, бокс.

**Путь ошибки**: удалить секрет ключа OpenRouter и повторить. Ожидается `degraded`,
понятное сообщение на странице и отказ запускать разбор — а не падение при первом же
запросе к модели.

## Проверка 1. Разбор одной записи (US1, US3)

Указать канал на странице, затем добавить конкретную запись вручную:

```bash
curl -s -X POST https://<адрес>/api/streams \
  -H "Authorization: Bearer $APP_ADMIN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"url":"https://www.twitch.tv/videos/<VOD_ID>"}' | jq
```

**Ожидается**: 202 и состояние `processing`; запись появляется в списке на странице.
Дальше бокс скачивает и режет аудио (около двух минут на семичасовой эфир), Worker
распознаёт куски и составляет документ. Для четырёхчасовой записи весь путь укладывается
в два часа (SC-005).

**Проверить документ** (FR-018, FR-031, SC-010):

```bash
curl -s https://<адрес>/api/streams/<VOD_ID>/document | head -40
```

Ожидается связный текст о стриме с заголовками разделов, временем и категориями. Читая
только его, за три минуты можно понять, о чём был эфир.

**Проверить покрытие** (FR-019, SC-008): временные границы разделов не должны оставлять
дыр длиннее нескольких минут на участках, где звучит речь.

## Проверка 2. Знания по запросу (US1)

```bash
curl -s -X POST https://<адрес>/api/knowledge/search \
  -H 'content-type: application/json' \
  -d '{"query":"<тема, звучавшая на стриме>","topK":5}' | jq
```

**Ожидается**: `found: true`, разделы отсортированы по оценке, у каждого — тема, полный
текст, категория, дата и ссылка с таймкодом.

**Проверено** (2026-09-16, запись `2873255697`, пять часов): 22 раздела, покрытие
сплошное от 0:00:00 до 5:16:59 без пропусков. Выборочно сверены с записью три раздела —
аудио в момент начала раздела скачано и распознано заново:

| Раздел | Что проверялось | Итог |
|--------|-----------------|------|
| Шоколадка от подписчика [0:08:20] | уборка, три ведра воды, казахская шоколадка от подписчика | совпало дословно |
| Планы по серверу SP6 [1:46:40] | сайт на Сашу Алабастера, Соня, Skin Lovers, вайп-кодинг против бренда SP | совпало дословно |
| История в торговом центре [5:01:40] | «Кирилл, ты чё», Соня перед ним, похожий рост и цвет волос | совпало дословно |

Выдуманного не нашлось, расхождение таймкода на границе раздела — 8 секунд при допуске
10. Разделы читаются без записи. Фильтр по категории возвращает только эту категорию,
поиск другими словами находит тот же раздел (совпало два из трёх первых).

**Порог отсечения был нерабочим.** С прежним значением `minScore` = 0.35 честный ответ
«сведений нет» был недостижим: запрос про рецепт борща возвращал пять разделов с оценками
около 0.6 и выглядел отвеченным. Измерено на двадцати посторонних запросах (рецепты,
погода, курс биткоина) — ни один не превысил 0.635, тогда как запросы по теме дают от
0.706. Порог поднят до 0.65: посторонний вопрос получает `found: false` и понятное
сообщение, тематический отвечается как прежде.

**Как проверить качество, а не формат**:

- открыть ссылку первого результата — речь по теме должна звучать не далее чем через
  10 секунд от начала (SC-003);
- прочитать текст, не открывая запись: он понятен сам по себе (SC-004);
- сверить утверждения с тем, что реально сказано, — выдуманного быть не должно (FR-016);
- убедиться, что вернулся раздел целиком, а не обрезанный кусок (FR-022).

**Отсутствие знаний** (FR-024):

```bash
curl -s -X POST https://<адрес>/api/knowledge/search \
  -H 'content-type: application/json' -d '{"query":"рецепт борща"}' | jq
```

Ожидается 200, `found: false`, понятное сообщение — не ошибка и не случайная выдача.

**Фильтр по категории** (FR-023): тот же запрос с `"category": "Just Chatting"` не должен
возвращать разделы из игровой части эфира.

**Поиск по смыслу** (FR-021): тот же вопрос другими словами возвращает тот же раздел.

## Проверка 3. Автоматическое пополнение (US2)

Дождаться появления новой записи на канале либо сдвинуть границу отслеживания назад.

**Ожидается**: запись берётся в работу без ручных действий и доходит до состояния
«разобрано» (FR-002).

**Дедупликация** (FR-005): после следующего срабатывания расписания повторного разбора не
происходит, число разделов не меняется.

**Запись для подписчиков** (FR-006): добавить такую запись вручную. Ожидается пометка
«пропущено» с причиной на странице и отсутствие повторных попыток на следующих запусках.

**Устойчивость** (FR-034, SC-009): прервать разбор на середине (остановить бокс). Ранее
разобранные трансляции остаются доступными; прерванная берётся заново на следующем
запуске.

## Проверка 4. Страница владельца (US3)

Открыть адрес сервиса.

**Ожидается**: список разобранных трансляций с датой, категориями и числом разделов
(FR-029); отдельный список пропущенных с причинами (FR-030); документ открывается по
клику (FR-031); на странице есть инструкция подключения ассистента с готовым адресом
(FR-032).

**Проверить, что список читается мимо Worker**: открыть вкладку сети в браузере — запрос
за списком идёт напрямую к реестру, а не к `/api/`.

## Проверка 5. Подключение ассистента (US1, FR-027, FR-032)

Добавить сервер ассистенту по инструкции со страницы:

```json
{
  "mcpServers": {
    "twitch-knowledge": { "type": "http", "url": "https://<адрес>/mcp" }
  }
}
```

**Ожидается**: ассистент видит инструменты `search_knowledge`, `knowledge_stats`,
`list_streams`; на вопрос по теме канала сам вызывает поиск и отвечает с опорой на
разделы, называя дату эфира; на вопрос вне базы сообщает, что сведений нет. Авторизация
не запрашивается. Подключение занимает меньше пяти минут (SC-011).

**Сверка с HTTP**: тот же вопрос через `POST /api/knowledge/search` даёт тот же набор
разделов в том же порядке.

## Проверка 6. Публичный доступ и его пределы (FR-028)

```bash
for i in $(seq 1 60); do
  curl -s -o /dev/null -w '%{http_code} ' -X POST https://<адрес>/api/knowledge/search \
    -H 'content-type: application/json' -d '{"query":"тест"}'
done; echo
```

**Ожидается**: после срабатывания ограничения приходят коды 429 с заголовком
`Retry-After`, а не отказ сервиса целиком. Запрос с другого адреса в это же время
обслуживается.

**Проверено** (2026-09-16): 60 запросов за 1,8 секунды — 48 обслужено, 12 отклонено с
кодом 429 и `Retry-After: 60`; страница в это же время отдавалась как обычно. Той же
серией, растянутой на минуту, ограничение не срабатывает вовсе — счётчик Cloudflare
сглаживает всплески и считает приблизительно, поэтому обслуженных больше заявленных
тридцати. Обслуживание с другого адреса не проверено: второго адреса под рукой не было.

**Проверить пределы входа**: запрос с полем `query` длиной в десять тысяч знаков
отклоняется с `invalid_input`, а не уходит в модель.

## Проверка 7. Нагрузка и параллельность (SC-002, SC-007)

Запустить разбор трансляции и одновременно слать запросы знаний:

```bash
for i in $(seq 1 10); do
  curl -s -o /dev/null -w '%{time_total}\n' -X POST https://<адрес>/api/knowledge/search \
    -H 'content-type: application/json' -d '{"query":"тест"}'
done
```

**Ожидается**: медиана меньше секунды, отказов нет, время ответа не растёт более чем
вдвое относительно спокойного периода.

**Проверено** (2026-09-16, по 20 запросов из России): в покое медиана 570 мс, худший
1263 мс; во время разбора медиана 565 мс, худший 1696 мс. Отказов нет, замедления по
медиане нет вовсе — разбор идёт отдельными вызовами Worker и на выдачу не влияет.

## Проверка 8. Чистота хранилищ

После завершения разбора:

```bash
wrangler r2 object list twitch-audio --prefix "audio/<VOD_ID>/"
```

**Ожидается**: пусто — куски удалены. Расшифровка не сохранена нигде: ни в документах, ни
в реестре, ни в векторной базе (FR-010).

**Расход бокса**: `box status runs --json` — процессорное время на разбор семичасового
эфира около 3,6 минуты; при пятичасовой месячной квоте это порядка восьмидесяти эфиров.

## Проверка 9. Удаление (FR-033)

```bash
curl -s -X DELETE https://<адрес>/api/streams/<VOD_ID> \
  -H "Authorization: Bearer $APP_ADMIN_TOKEN" | jq
```

**Ожидается**: возвращено число удалённых кусков; повторный поиск по теме этой записи
ничего не находит; документ и запись исчезают из списка на странице; другие трансляции
не затронуты.

## Автоматические тесты

```bash
bun test              # модульные и контрактные
bun run build         # сборка интерфейса
wrangler deploy --dry-run
```

Сквозная проверка конвейера выполняется на коротком фрагменте записи — двухминутном
отрезке, — чтобы не тратить минуты распознавания на каждый прогон.
