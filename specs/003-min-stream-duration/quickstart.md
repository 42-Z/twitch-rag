# Проверка: обрывки трансляций не берутся в разбор

**Дата**: 2026-09-19 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

Проверки идут от дешёвых к дорогим. Первые три выполняются на своём компьютере и не
тратят денег; последняя — приёмочная, она делается после выпуска и на настоящем эфире.

## Подготовка

```sh
bun install
```

Для проверок, где нужен Worker, — запуск местного сервера с обработчиком расписания:

```sh
bunx wrangler dev --test-scheduled
```

Обработчик расписания вызывается вручную по адресу, который открывает этот ключ:
`GET http://localhost:8787/cdn-cgi/local/scheduled` (при необходимости с
`?cron=*+*+*+*+*`). Ключ и путь — из
[документации Wrangler](https://developers.cloudflare.com/workers/wrangler/commands/workers/).

> Местный Worker ходит в те же хранилища, что и боевой: ключи берутся из `.env`. Всё, что
> ниже, пишет в боевой реестр, а потому каждый шаг заканчивается уборкой за собой.

## 1. Граница длительности

```sh
bun test tests/unit/
```

Ожидается: запись в 179 секунд в разбор не берётся, в 180 — берётся, в 181 — берётся;
запись с нулевой длительностью не берётся и получает ту же причину, что и обрывок;
запись короче трёх минут не становится ни `processing`, ни `ready`, ни `failed`.

## 2. Короткая запись не занимает очередь

Там же, модульной проверкой: в списке записей канала есть обрывок и после него настоящая
запись, появившаяся после подключения канала; после прохода пометки обрывок оказывается
пропущенным с причиной, а к разбору выбирается настоящая запись — то есть проход не
отнимает у неё запуск и не мешает отбору.

Отдельно: обрывок, появившийся **до** подключения канала, не помечается вовсе — в список
пропущенных он не попадает.

## 3. Ответ на добавление короткой записи

```sh
curl -s -X POST localhost:8787/api/streams \
  -H "Authorization: Bearer $APP_ADMIN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"vodId":"2830322015"}'
```

`2830322015` — настоящий обрывок в архиве канала длительностью 16 секунд. Ожидается ответ
`200` с телом `{"vodId":"2830322015","status":"skipped","reason":"Запись короче трёх минут — разбирать в ней нечего."}`
и никакой работы после него: в журнале Worker нет ни скачивания записи, ни обращения к
распознаванию речи.

Затем то же для повторного разбора — ответ такой же:

```sh
curl -s -X POST localhost:8787/api/streams/2830322015/reparse \
  -H "Authorization: Bearer $APP_ADMIN_TOKEN"
```

Уборка: `curl -s -X DELETE localhost:8787/api/streams/2830322015 -H "Authorization: Bearer $APP_ADMIN_TOKEN"`.

## 4. Вид в списке пропущенных

Открыть раздел «Управление» страницы, предъявить токен владельца и найти в списке
пропущенных записей строку с причиной «Запись короче трёх минут — разбирать в ней нечего».
Причина должна читаться человеком и объяснять, почему записи нет в базе.

Тот же текст обязан прийти и в подписи под формой добавления — не «Запись принята в
обработку», а причина пропуска.

## 5. Приёмочная проверка (после выпуска)

Делается тогда, когда у канала случится неудавшийся запуск эфира, — раньше проверить
нечего: после подключения канала коротких записей нет.

- Обрывок появляется в списке пропущенных не позже чем через час после эфира, с причиной
  о трёх минутах.
- В журнале Worker по этому идентификатору нет ни скачивания записи из архива площадки, ни
  обращения к распознаванию речи.
- Следующая настоящая запись разбирается в тот же час, а не через час после обрывка.
