# Контракты: что меняется против `001-stream-archive-rag`

**Дата**: 2026-09-19 | **Спецификация**: [../spec.md](../spec.md)

Контракты 001 остаются в силе (с учётом изменений из
[002-document-quality](../../002-document-quality/contracts/knowledge-api.md)). Ниже —
только то, что меняется здесь: ответ двух управляющих действий, когда запись не берётся
в разбор. Формат описания и коды ошибок — те же, что в
`001-stream-archive-rag/contracts/knowledge-api.md`.

## POST /api/streams — ответ зависит от исхода

Запись короче трёх минут в разбор не берётся и становится пропущенной с причиной
(FR-001, FR-003). Сегодня ответ был `202 { "status": "processing" }` при любом исходе, и
для такой записи он обещал работу, которой не будет.

**Разбор начат** — как прежде:

```http
HTTP/1.1 202 Accepted
```

```json
{ "vodId": "2345678901", "status": "processing" }
```

**Запись не взята в разбор** — `200` со состоянием `skipped` и причиной:

```http
HTTP/1.1 200 OK
```

```json
{
  "vodId": "2345678901",
  "status": "skipped",
  "reason": "Запись короче трёх минут — разбирать в ней нечего."
}
```

`reason` — тот же текст, что ложится в реестр и показывается в списке пропущенных
(FR-030 спецификации 001). Одно и то же значение в обоих местах обязательно: расхождение
означало бы, что владелец прочитал одно, а увидел другое.

Не взята в разбор запись может быть по трём причинам: слишком коротка, доступна не всем
зрителям, нулевой длительности. Ответ у них один и тот же по форме — различает их текст
причины, а не код ответа.

Код ответа, а не только поле `status`, отличает начатую работу от пропуска: клиент, не
читающий тело, иначе счёл бы пропуск начатым разбором. Ошибкой (`4xx`) пропуск не
объявляется: владелец сделал всё правильно, а запись просто не подлежит разбору.
Уже разобранная запись отвечает ошибкой `already_processed`, как и прежде.

## POST /api/streams/:vodId/reparse — то же различие

Повторный разбор идёт тем же путём, поэтому отвечает так же: `202` и `processing`, если
разбор начат, `200`, `skipped` и `reason`, если запись не взята. Для короткой записи это
единственный возможный исход: разобрать её нельзя, и прежний ответ `202` был неправдой.

Прочие ответы этого действия (`not_found` для неизвестной записи, `reparse_running` для
идущего разбора) не меняются.
