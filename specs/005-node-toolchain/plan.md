# Implementation Plan: Переезд на Node, Vite и Vitest

**Branch**: `005-node-toolchain` | **Date**: 2026-09-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-node-toolchain/spec.md`

## Summary

Проект переходит с Bun на Node.js и npm. Сборка страницы переезжает на Vite с
официальным плагином Tailwind для Vite, сборка программы конвейера — на esbuild,
проверки — на Vitest 4.1 с двумя наборами: чистая логика и Worker'а. Сборка самого
Worker'а остаётся на Wrangler — вместе с выпуском, который не меняется. Ради этого
переезда всё и делается: с Vitest становится доступна встроенная проверка Cloudflare,
исполняющая тесты внутри среды исполнения Worker'а, с настоящими привязками.

Проверки страницы в браузере остаются на Playwright, как и были; у них меняются только
команды запуска.

## Technical Context

**Language/Version**: TypeScript 5.8+ (требование Node для устойчивого исполнения без
сборки), Node.js 24.20, npm 11.19 — оба уже стоят на машине

**Primary Dependencies**: уходят `@types/bun`, `bun-plugin-tailwind`, `bunfig.toml`,
`bun.lock`; приходят `vitest@^4.1.0` (не пятая версия), `@cloudflare/vitest-plugin`,
`vite`, `@vitejs/plugin-react`, `@tailwindcss/vite`, `esbuild`, `@types/node`

**Storage**: не меняется — Upstash (реестр, вектор, документы), R2 в Cloudflare

**Testing**: `npm test` — Vitest: два набора (чистая логика под Node; Worker'а внутри
среды исполнения через плагин Cloudflare). `npm run test:e2e` — Playwright с проверочным
набором Wrangler, запускающий Node

**Target Platform**: Cloudflare Workers (выпуск), машина у Upstash (конвейер), Node —
разработка

**Constraints**: Node не читает `tsconfig.json` — псевдонимы и `.tsx` для него не
существуют; устойчивое исполнение TypeScript без сборки с 24.12; плагин Cloudflare
требует Vitest 4.1 и `compatibility_date` не старее 2022-10-31 (у нас 2026-09-15);
плагин сам включает `nodejs_compat` — у нас он уже включён; покрытие в среде Worker'а
считается только инструментированием

**Scale/Scope**: 61 файл исходников, 28 файлов проверок (~3 560 строк), один Worker,
одна страница, одна консольная программа

## Решения

### 1. Пакеты: npm и замок npm

`bun.lock` удаляется, замок строится заново `npm install`. Документация npm про чужие
замки не знает вовсе: он видит только `package-lock.json` и `yarn.lock`, поэтому
задокументированного переноса не существует, а два замка рядом означают, что установка
может пойти по любому.

### 2. Секреты: явный флаг вместо автозагрузки

Автоподхвата `.env` у Node нет: переменные подгружает `--env-file`, и он ставится в
каждую команду, которой они нужны. Отдельно учтено задокументированное поведение
`node --run`: переменные, загруженные флагом, в запускаемый скрипт не передаются, —
поэтому скрипты запускаются через `npm run`, а флаг стоит внутри самих команд.

### 3. Две ветки TypeScript вместо одной

Node не читает `tsconfig.json`: ни псевдонимов, ни `.tsx` он не знает, зато исполняет
обычный TypeScript без сборки. Отсюда две настройки: для кода, который Node исполняет
сам (Worker, конвейер), — `module: nodenext`; для того, что уходит в сборщик (страница,
проверки в браузере), — `bundler`. Разделение предписано документацией Node, а не выбрано.

### 4. Страница: Vite с корнем в папке страницы

Точка входа — `src/ui/index.html`, поэтому корнем сборки объявляется сама папка: иначе,
как показала проверка сборкой, страница уезжает в `dist/src/ui/index.html`, а раздача
статики Cloudflare на неизвестный адрес отдаёт `/index.html` — и приложение ломается
молча. Итог сборки кладётся в `dist` абсолютным путём: относительный считается от корня
сборки, а не от корня проекта.

Значения, закладываемые в страницу, переезжают на `import.meta.env` с приставкой
`VITE_` — это документированный способ. Проверка «не задано — падать» сохраняется:
без неё `process.env` в браузерном коде превращается в пустую ссылку и страница уезжает
нерабочей, не сказав ни слова. Имена значений меняются, поэтому их надо переименовать и
в настройках сборки Cloudflare.

### 5. Worker: сборка и выпуск остаются на Wrangler

Плагин Cloudflare для Vite не внедряется. Документация называет его полноценной заменой
встроенной сборки Wrangler — то есть это две равноправные ветки, а не «новое вместо
старого». Плагин дал бы единую сборку и горячую перезагрузку, но потребовал бы перевести
на него весь Worker вместе с расписанием, Workflows и ограничителем частоты, поддержка
которых в нём не проверена. Выпуск при этом не меняется: сборка плюс развёртывание,
слияние в основную ветку остаётся выпуском.

### 6. Программа конвейера: esbuild

Программа уезжает в машину у Upstash одним файлом, без папки зависимостей. В ней есть
верхнеуровневый `await`, а документация esbuild прямо говорит, что вложение такого кода
возможно только при выводе в формате модулей. Он же исключает встроенные модули Node
автоматически и вкладывает внутрь обычные зависимости — то есть самодостаточный файл
получается одной командой.

Отвергнуто: Rolldown — современнее и приезжает вместе с Vite, но документация Vite не
описывает сборку консольных программ и отсылает для этого к Rolldown напрямую, а это
лишний инструмент ради одной команды. Отвергнуто: сборка Vite в режиме для серверного
кода — она оставляет зависимости внешними, а внешних зависимостей в машине нет.

### 7. Проверки: Vitest 4.1 и два набора

Берётся четвёртая версия, а не пятая: плагин Cloudflare заявляет совместимость с
`^4.1.0`, и совместимость с пятой не заявлена нигде. Разделение наборов — штатным
`test.projects`: чистая логика под Node, Worker внутри его среды исполнения. Плагин
подключается только у набора Worker'а: хуки плагинов из корневого настройки выполняются
всегда, и в корне он распространился бы на весь прогон.

Перенос существующих проверок механический: они используют пять имён из прежнего
запускающего и ни одного мока.

### 8. Порядок работ, при котором каждый шаг зелёный

1. Пакеты и скрипты: npm, замок, типы, `.env`.
2. Проверки на Vitest — без изменения того, что они проверяют.
3. Сборка страницы на Vite.
4. Сборка программы конвейера на esbuild и её перекладывание в машину.
5. Набор проверок Worker'а на плагине Cloudflare — то, ради чего переезд.
6. Инструкции и настройки сборки в Cloudflare.

Порядок не случаен: проверки — единственное, что страхует остальные шаги, поэтому они
переезжают первыми и до конца. Набор Worker'а идёт последним, потому что до него
переезд уже закончен, а он — приобретение, а не условие.
