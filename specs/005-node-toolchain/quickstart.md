# Проверка переезда

**Дата**: 2026-09-19 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

Проверки идут от дешёвых к дорогим: сначала на своей машине, потом на собранной странице,
потом в браузере. Всё, что требует выпуска, — приёмочные, они в конце и в список задач не
входят.

## Подготовка

```sh
npm ci
```

Установка идёт по замку npm. Прежнего замка в проекте быть не должно: два замка рядом
означают, что установка может пойти по любому.

## 1. Прежняя среда не участвует

```sh
grep -rn "bun" package.json tsconfig*.json .gitignore CLAUDE.md README.md
```

Ожидается: упоминаний прежней среды нет, кроме описания самого переезда в спецификациях.
Отдельно проверить, что `bun.lock` и `bunfig.toml` удалены, а `@types/bun` и
`bun-plugin-tailwind` не числятся в зависимостях.

## 2. Проверки чистой логики

```sh
npm test
```

Ожидается: проходит столько же проверок, сколько до переезда, и ни одна не потеряна.
Число проверок до переезда — 230 проходящих и 1 пропущенная; оно должно сохраниться.

Время прогона: подъём среды Worker'а при этом не должен происходить — набор логики идёт под
Node.

## 3. Проверки Worker'а в его среде

```sh
npx vitest run --project workers
```

Ожидается: проверки исполняются внутри среды исполнения Worker'а и видят настоящие привязки.

Отдельно, руками: **испортить имя привязки** в настройке (например, `AUDIO` → `AUDIO_TYPO`)
и убедиться, что хотя бы одна проверка падает с понятной причиной. Затем вернуть как было.
Это тот случай, который до переезда не ловился ничем.

## 4. Страница собирается

```sh
npm run build
```

Ожидается: результат лежит в `dist`, и **страница — именно `dist/index.html`**, а не
`dist/<какой-то путь>/index.html`. Второе означает молчаливую поломку раздачи статики.

Проверить, что сборка **падает**, если не заданы значения для страницы:

```sh
env -u VITE_REGISTRY_URL -u VITE_REGISTRY_READONLY_TOKEN npm run build
```

Ожидается: отказ с названием недостающего значения, а не собранная нерабочая страница.

## 5. Страница работает в браузере

```sh
npm run test:e2e
```

Ожидается: проверки страницы проходят — подпись после добавления записи и поведение кнопки
повторного разбора. Это те же проверки, что были до переезда: они и есть страховка, что
сборка не изменила поведение страницы.

## 6. Программа конвейера собирается

```sh
npm run build:pipeline
```

Ожидается: получился один файл `pipeline.mjs`, запускаемый Node без папки зависимостей.
Проверить, что в нём нет внешних импортов, кроме встроенных модулей Node:

```sh
grep -o 'from "[^"]*"' pipeline.mjs | sort -u
```

## 7. Приёмочные проверки (после выпуска)

Делаются после слияния в основную ветку и в список задач не входят.

- Сборочная среда Cloudflare собирает и выпускает сервис без ручных действий: команда сборки
  и значения сборки переименованы там же, где задавались.
- Страница по боевому адресу открывается, список трансляций читается, документ открывается.
- Программа конвейера переложена в машину у Upstash и разбор новой записи проходит ею:
  прежняя сборка там больше не годится.
- Часовая проверка и разбор идущего эфира работают как прежде — переезд их не касался.
