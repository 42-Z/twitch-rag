# Контракт: внешние точки доступа

**Спецификация**: [spec.md](../spec.md) | **Модель данных**: [data-model.md](../data-model.md)

Меняется одно: там, где в адресе или в ответе стоял номер записи площадки, теперь стоит
идентификатор записи (`streamId`). Для неделёного эфира он выглядит как прежде, поэтому
существующие адреса продолжают работать.

## Пути с идентификатором записи

| Метод и путь | Было | Стало |
|---|---|---|
| `GET /api/streams/{id}/document` | `{id}` — цифры | `{id}` — `^\d{1,20}(-p\d{1,3})?$` |
| `POST /api/streams/{id}/reparse` | то же | то же |
| `DELETE /api/streams/{id}` | то же | то же |
| `GET /knowledge/{id}` (страница) | то же | то же |

Идентификатор, не подходящий под образец, отвергается с ошибкой разбора входа **до**
обращения к хранилищам. Сегодня три из этих путей формат не проверяют вовсе, а удаление
сносит векторы по префиксу — расширение формата без проверки означало бы удаление по
произвольной строке.

## `POST /api/streams` — добавление записи владельцем

Тело без изменений: `{ url }` или `{ vodId }` — владелец добавляет **запись площадки**, а
не часть. Деление применяется сервисом.

Ответ сообщает, что запись поделена: сколько частей и какая взята в разбор первой.
Владелец, добавивший девятичасовой эфир, не должен гадать, почему разбирается «половина».

## `GET /api/streams` и чтение реестра страницей

К полям записи добавляются `part`, `partCount`, `vodId`. Страница показывает часть и
общее число частей и строит адрес документа по идентификатору записи, а ссылку на
площадку — по `vodId`.

## Поиск по знаниям и MCP

В найденном фрагменте:

| Поле | Значение |
|---|---|
| `id` | `<streamId>:<номер раздела>` |
| `stream.vodId` | номер записи площадки |
| `stream.streamId` | запись, которой принадлежит фрагмент |
| `stream.title` | имя документа части |
| `url` | ссылка на момент исходной записи, абсолютное время |

Ответ остаётся совместимым: `vodId` никуда не делся и по-прежнему указывает на видео
площадки.

## `POST /api/internal/ingest-ready` — сигнал конвейера

Тело дополняется:

| Поле | Смысл |
|---|---|
| `streamId` | запись, для которой готово аудио |
| `partStartSeconds` | начало части от начала эфира; у неделёной записи 0 |
| `partCount` | всего частей у эфира |

Поле `vodId` остаётся — по нему сервис обращается к площадке.

`offsetSeconds` каждого куска приходит **абсолютным**, от начала эфира: конвейер знает
границы отрезка и прибавляет смещение сам. Так смещение прибавляется в одном месте, а
дальше по всему разбору время уже абсолютное.

Проверка секрета, защита от повторного запуска разбора и обработка отказов конвейера — без
изменений, но привязаны к `streamId`: две части одного эфира — два разных разбора.
