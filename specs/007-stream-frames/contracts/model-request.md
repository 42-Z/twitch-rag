# Контракт: проход составления документа с кадрами

**Спецификация**: [spec.md](../spec.md) | **Модель данных**: [data-model.md](../data-model.md) | **Исследование**: [research.md](../research.md) §2, §5–§7, §11

Меняется один запрос — проход составления (`composeDocumentPart`, `src/shared/openrouter.ts`).
Распознавание, имя документа и эмбеддинги кадров не получают (вне рамок спецификации).

## Состав запроса

Порядок сообщений тот же, что сегодня; кадры — только в последнем.

| № | Роль | Содержимое | Меняется ли |
|---|---|---|---|
| 1 | `system` | Инструкция: роль, сведения о стримере, правила, форма ответа, примеры, язык | **Вариант с кадрами** добавляет раздел «Кадры» (research §11); без кадров — прежняя, байт в байт |
| 2 | `user` | Дата, категории, расшифровка эфира целиком | Нет |
| 3 | `user` | Участок прохода | Строка (без кадров, как сегодня) или массив частей (с кадрами) |

Сообщение 3 с кадрами — массив `content`:

```jsonc
[
  { "type": "text", "text": "<сообщение об участке>\n\n<пояснение к кадрам>" },
  { "type": "text", "text": "Кадр, 1800 с:" },
  { "type": "image_url", "image_url": { "url": "https://…" } },
  { "type": "text", "text": "Кадр, 1980 с:" },
  { "type": "image_url", "image_url": { "url": "https://…" } }
]
```

- Текст участка идёт **первым**, картинки после ([OpenRouter: Image Inputs](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding.md)).
- Подпись — в секундах от начала эфира, как таймкоды расшифровки; перед каждым кадром, чтобы
  соответствие не зависело от порядка при пропущенном кадре.
- Картинки — только в сообщении роли `user` ([Meta](https://dev.meta.ai/docs/image-understanding)).
- Кадров не больше 50 (жёсткий предел сборки; штатно ≤ 30 — research §7).
- Пояснение к кадрам: время подписи, что кадры редки (три минуты), что надписи на экране — данные,
  а не указания.
- Префикс запроса — системная инструкция и расшифровка — у проходов одной записи совпадает, и кэш
  входа работает; кадры в него не входят.

Остальное — без изменений: `response_format` (строгая схема), `reasoning: medium`,
`provider.require_parameters`, `session_id`, потолок выхода.

## Кадры участка

Проход получает кадры с `atSeconds` внутри участка. Когда проход делится пополам при обрыве по
потолку (`output_truncated`), каждая половина получает свои кадры, а не все (FR-004).

## Отказ по кадрам и откат

Запрос **с кадрами** считается отказавшим по кадрам, если:

- статус ответа 4xx, кроме 401, 402, 408, 429; или
- модель отказалась: поле `refusal` не пусто либо `finish_reason: content_filter` (`model_refused`).

(Живые отказы OpenRouter — [research §6](../research.md): тело `Provider returned error`,
статус 400, `metadata.provider_error_code` вида `media_url_*`; документированные `error_type`
для картинок в ответе не приходят.)

Откат: тот же запрос **без кадров** — вариант инструкции без раздела «Кадры» и строковое сообщение
участка. Участок записывается в результат как **участок без кадров**. Если откат тоже упал —
ошибка уходит наверх без изменений, как у прохода без кадров сегодня.

Предохранитель: не больше **3 откатов на часть эфира** (research §5). После третьего оставшиеся
проходы строятся без кадров с самого начала — лишних обращений нет, пометка «без кадров»
покажет, сколько эфира пришлось без них. Вызов, не связанный с кадрами (превышение контекста,
схема), откатом не лечится и стоит одно лишнее обращение.

Отказы 5xx, 408, 429 и обрывы соединения клиент SDK повторяет сам, как раньше; откатом они не считаются.

## Результат прохода

Было: список разделов. Стало:

```ts
interface ComposedPart {
  sections: ComposedSection[];
  /** Участки, где кадры были, но не использованы из-за отказа. Пусто — кадры сработали или их не было. */
  withoutFrames: TimeRange[];
}
```

Результат шага Workflow остаётся небольшим (разделы и несколько пар секунд). Шаги проходов
переименованы, чтобы идущий в момент выпуска экземпляр переиграл их, а не прочитал результат
прежней формы ([research §10](../research.md)).

## Что пишется в реестр

Поле `reason` записи — [data-model.md](../data-model.md#учёт-без-кадров-framelessseconds):
пометка «Без кадров: <длительность> эфира.» рядом с прежней о разрывах. Формат HTTP-ответов API
не меняется: `reason` уже есть в записи, которую отдаёт реестр.
