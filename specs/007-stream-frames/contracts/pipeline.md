# Контракт: кадры в прогоне бокса

**Спецификация**: [spec.md](../spec.md) | **Модель данных**: [data-model.md](../data-model.md) | **Предыдущий контракт**: [`006/contracts/pipeline.md`](../../006-split-long-streams/contracts/pipeline.md)

Расширение контракта `006`, а не замена: аргументы запуска и порядок выпуска те же. Меняется то,
что конвейер делает после выгрузки звука, и тело сигнала готовности.

## Аргументы запуска

Без изменений: `--stream`, `--from`, `--to`, `--url`, `--callback`, прежний `--vod`. Интервал между
кадрами — не аргумент, а константа `FRAME_INTERVAL_SECONDS` в `src/shared/frames.ts` (FR-002): значение в
одном месте, выключателя у владельца нет (вне рамок спецификации).

## Что делает конвейер

После нарезки и выгрузки звука, **до** сигнала:

1. Из того же `yt-dlp --dump-json`, что даёт сведения о записи, берётся источник кадров: формат с
   плейлистом HLS (`protocol: m3u8_native`), у которого есть видео; из подходящих — с наибольшей
   высотой не выше 720, а если таких нет, с наименьшей выше. Источника нет (звук без видео) —
   кадров нет, шаги ниже пропускаются.
2. Плейлист скачивается один раз; по `#EXTINF` строится таблица «сегмент → начало, длительность,
   адрес» (адрес — из плейлиста, не по номеру).
3. Для каждого окна отрезка (`frameWindows(from, to)`, [data-model](../data-model.md#окно-кадра-framewindow))
   берётся сегмент, содержащий его середину; сегмент скачивается, из него `ffmpeg` снимает первый
   кадр (`-frames:v 1 -q:v 4`, не шире 1280 px, JPEG).
4. Кадр кладётся в R2 под ключ `frames/<streamId>/frame-<atSeconds, 6 цифр>.jpg`
   (`content-type: image/jpeg`); `atSeconds` — начало сегмента (целое число секунд, округление вниз).
5. Для объекта считается подписанная ссылка на чтение со сроком **21 600 с** (6 ч).
6. Окна обрабатываются **по очереди**; на загрузку сегмента и запись в R2 — до четырёх попыток, как
   у звука.

**Любая неудача кадра — пропуск этого кадра.** Сегмент не скачался, `ffmpeg` не отдал кадр, результат
пуст или не начинается с маркера JPEG (`FF D8`), запись в R2 не прошла — кадр в список не попадает, остальные
идут. Ошибка добычи в целом (плейлист не открылся, источника нет) даёт пустой список. **Ни одна ошибка добычи не роняет
прогон** и не меняет код выхода: кадры — добавка к звуку (FR-014, FR-016). Сообщение об ошибке
пишется в журнал прогона без адресов.

Память и диск: сегмент (≈4,3 МБ) живёт в памяти одного шага цикла, на диск не пишется. Рабочий
каталог звука по-прежнему убирается в `finally`.

## Сигнал готовности

К телу из `006` добавляется необязательное поле:

```jsonc
{
  "streamId": "2878430068-p2",
  // … прежние поля …
  "frames": [
    { "atSeconds": 21690, "url": "https://<account>.r2.cloudflarestorage.com/twitch-audio/frames/2878430068-p2/frame-021690.jpg?X-Amz-…" }
  ]
}
```

- `frames` — по возрастанию `atSeconds`, только удавшиеся кадры; пустой массив допустим и равен
  отсутствию поля.
- `atSeconds` — абсолютное время от начала эфира, как `offsetSeconds` кусков.
- Размер: 385 знаков на ссылку, штатно ≤ 120 кадров (46 200 Б).

## Что проверяет Worker

Сигнал аутентифицирован общим секретом, но ссылки из него уходят дальше — их скачивает чужой
сервис, — поэтому каждая проверяется (`routes/internal.ts`). Ошибка в записи **отбрасывает эту
запись, а не сигнал**: разбор важнее одной картинки.

| Проверка | Отбрасывается, если |
|---|---|
| Форма | не объект с целым `atSeconds ≥ 0` и строкой `url` длиной ≤ 1 000 |
| Адрес | не `https:`, хост не оканчивается на `.r2.cloudflarestorage.com`, путь не содержит `/frames/<streamId>/` |
| Время | вне `[partStart, partStart + durationSeconds)` |
| Повтор | та же секунда уже есть |
| Число | записей больше 400 — остаются первые 400 по времени |

Отброшенное считается недобытым и попадает в учёт «без кадров». В журнал пишется число отброшенных,
не адреса.

## Совместимость

| Бокс | Worker | Поведение |
|---|---|---|
| Прежний | Новый | Поля `frames` нет → кадров нет, документ по речи, запись говорит «Без кадров: <весь эфир>» |
| Новый | Прежний | Поле игнорируется (параметры строятся по полям), документ по речи; кадры остаются в R2 до уборки по возрасту после выпуска нового Worker |
| Новый | Новый | Кадры есть |

Прежняя программа сигнала с `frames` не посылает, и ей это не нужно. Откат на `pipeline.prev.mjs`
безопасен.

## Порядок выпуска

Как в `006`: сначала `npm run build:pipeline` и `box files write /workspace/home/pipeline.mjs`,
затем слияние. Обратный порядок тоже безопасен (таблица выше), но кадров не даёт до тех пор,
пока не лежит новая программа. Если интервал между кадрами когда-либо меняется, обе стороны
выпускаются одной парой: при расхождении окна считаются по-разному, и пометка «без кадров»
покажет лишнее.
