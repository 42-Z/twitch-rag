# Модель данных: кадры

**Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md) | **Контракты**: [contracts/](./contracts/)

Новых хранилищ и новых полей реестра нет. Кадр живёт в хранилище аудио (R2) на время разбора и в
параметрах экземпляра Workflow как ссылка; в документ, знания и реестр он не попадает ничем,
кроме текста пометки «без кадров».

## Кадр (`Frame`)

Изображение экрана эфира в один момент — `src/shared/frames.ts`.

| Поле | Тип | Смысл |
|---|---|---|
| `atSeconds` | целое, ≥ 0 | Момент от начала эфира — **начало сегмента**, из которого снят кадр (абсолютное время, как у расшифровки; FR-003) |
| `url` | строка https | Подписанная ссылка на чтение объекта в R2, действует 6 часов |

Объект в R2: ключ `frames/<streamId>/frame-<atSeconds, 6 цифр>.jpg`, JPEG не шире 1280 px,
`content-type: image/jpeg`. Ключ определяется моментом, поэтому повторный прогон записи перезаписывает
те же объекты (FR-019). Ссылка — носитель доступа до истечения подписи, поэтому в журналы и в
результаты шагов она не пишется.

**Правила**

- Кадров у части — не больше 400 в сигнале (проверка на входе; штатно ≤ 120).
- `atSeconds` внутри отрезка части: `[partStart, partStart + duration)`. Расчётный момент окна
  отстоит от его начала не меньше чем на 45 с, а сегмент начинается не раньше чем за 10 с до
  расчётного момента, так что снятый кадр отрезка не покидает. Вне отрезка — запись игнорируется.
- Два кадра с одной секундой — остаётся первый. Порядок после приёма — по возрастанию `atSeconds`.
- Некорректный кадр в сигнале отбрасывается один, сигнал принимается (FR-016): разбор нужен
  важнее, чем одна картинка.

## Окно кадра (`FrameWindow`)

Чисто расчётное понятие, хранимых полей нет. Отрезок `[from, to)` длиной `L` делится на
`n = max(1, round(L ÷ 180))` окон равной длины; `k`-е окно — `[from + k·L/n, from + (k+1)·L/n)`;
**расчётный момент** — его середина. Интервал 180 с — константа `FRAME_INTERVAL_SECONDS` в одном
месте (FR-002), её читают и конвейер, и Worker.

Окно **покрыто**, если в нём есть кадр (`atSeconds` в границах окна) и проход, писавший этот
участок, его не терял при откате без кадров. Непокрытые окна дают пометку «без кадров» (FR-015).

## Кадры прохода (`PassFrames`)

Хранимых полей нет. Проход, пишущий участок `[start, end)`, получает кадры с `atSeconds` внутри
участка (FR-004), по возрастанию. Если их больше 50 — равномерная выборка 50 (жёсткий предел
запроса); число проходов с самого начала не даёт этому случиться (plan, И5).

Проход, у которого запрос с кадрами закончился отказом (контракт
[model-request.md](./contracts/model-request.md)), переписывается без них и записывает в результат
**участки без кадров** — список `TimeRange` (если участок делился при обрыве по потолку, то только
те его половины, что откатились).

## Учёт «без кадров» (`framelessSeconds`)

Сумма длин непокрытых окон отрезка — целое число секунд. Считается чистой функцией от отрезка,
списка кадров сигнала и участков без кадров всех проходов.

| Случай | Результат |
|---|---|
| Все окна покрыты | 0 — пометки нет |
| Кадров в сигнале нет вовсе (прежний конвейер, нет видео, сбой добычи) | длина отрезка |
| Часть кадров не добыта | сумма длин их окон |
| Проход откатился без кадров | к недобытым добавляются его окна с кадрами |

**Пометка в реестре.** Поле `reason` записи — то же, что сегодня несёт «Разделы не покрывают…»:

- нет ни разрывов, ни «без кадров» → пустая строка (как сейчас);
- есть оба → «Разделы не покрывают 12 мин эфира. Без кадров: 40 мин эфира.»;
- только кадры → «Без кадров: 40 мин эфира.»

Длительность — тем же `formatDuration`, что у разрывов. Страница показывает `reason` у готовых записей
без изменений (`StreamList.tsx`), поэтому интерфейс не меняется. Причина сбоя разбора в реестр по-прежнему
не идёт (она остаётся в журнале).

## Параметры разбора (`IngestParams`) и сигнал бокса

К `IngestParams` добавляется необязательное `frames?: Frame[]`; отсутствие равно пустому списку.
К сигналу готовности — то же необязательное поле. Подробно — [contracts/pipeline.md](./contracts/pipeline.md).

## Состояния

Состояний записи не добавляется. Кадры не меняют жизненный цикл `processing → ready/failed/skipped`:

```
бокс снял кадры ─► сигнал со ссылками ─► проходы составления (кадры своего участка)
                                              │
                      отказ по кадрам ──► проход без кадров (≤ 3 раза на часть) ──► дальше без кадров
                                              │
                    ready (reason: «Без кадров…» при необходимости) ─► убрать frames/<streamId>/
                    failed (не сбой движка)                       ─► убрать frames/<streamId>/
```
