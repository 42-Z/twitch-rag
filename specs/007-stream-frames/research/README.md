# Стенд качества: что дают кадры эфира

Спецификация 007 обещает, что документ с кадрами называет предмет, на который указывает
речь, исправляет искажённые имена и при этом не выдумывает и не раскрывает лишнего. Стенд
проверяет это на настоящей записи до выпуска: критерии SC-001…SC-006 из
[spec.md](../spec.md).

## Как повторить

Нужны `OPENROUTER_API_KEY` в `.env`, `yt-dlp` и `ffmpeg`. Расшифровка участка записи
`2875806701` (20:00–90:00) уже лежит в `specs/002-document-quality/research/data/` и повторно не
распознаётся. Всё запускается из корня проекта.

```sh
# 1. Кадры участка тем же кодом, что в конвейере (≈23 кадра, 3–5 минут)
node --env-file=.env specs/007-stream-frames/research/scripts/get-frames.ts \
  --vod 2875806701 --from 1200 --to 5400

# 2. Проходы составления без кадров и с кадрами по боевой инструкции
node --env-file=.env specs/007-stream-frames/research/scripts/measure-frames.ts \
  --transcript 2875806701-1200-5400 --frames 2875806701-1200-5400 --tag run1

# 3. Счёт контрольных мест по готовым документам (SC-001, SC-002)
node specs/007-stream-frames/research/scripts/measure-frames.ts \
  --check specs/007-stream-frames/research/data/control-places.json --docs 2875806701-1200-5400-run1

# 4. Нарисованные кадры с секретами и приказами среди настоящих (SC-005, SC-006):
#    сначала рисуются (ffmpeg, шрифт с кириллицей), потом гоняются по одному набору
node specs/007-stream-frames/research/scripts/draw-probes.ts --frames 2875806701-1200-5400
node --env-file=.env specs/007-stream-frames/research/scripts/measure-frames.ts \
  --transcript 2875806701-1200-5400 --frames 2875806701-1200-5400 --probes secrets --tag run1-secrets
node --env-file=.env specs/007-stream-frames/research/scripts/measure-frames.ts \
  --transcript 2875806701-1200-5400 --frames 2875806701-1200-5400 --probes orders --tag run1-orders
```

Ключи `measure-frames.ts`: `--tag` — метка прогона, чтобы новые файлы не затирали прежние;
`--part-minutes` — проходы фиксированной длины вместо боевого деления; `--variants base,frames`
— какие варианты гонять; `--streamer-info` — сведения о стримере (по умолчанию пусто: стенд
меряет вклад кадров, а не сведений), `--streamer-info-file <файл>` — те же сведения из
ограждённого блока ``` файла, например `specs/002-document-quality/streamer-info.md`;
`--probes secrets|orders` — десять настоящих кадров заменяются нарисованными, гоняется один
вариант, с кадрами; печатается, что просочилось, и сколько проходов осталось без разделов.

Ключи для сравнения моделей и правок инструкции (боевой запрос они не меняют): `--model` и
`--effort` — подменить модель и уровень рассуждения; `--max-output N` — потолок токенов выхода
прохода, верхняя граница цены (рассуждение входит); `--no-temperature` и `--no-reasoning` — убрать
поле из запроса, если у модели его нет; `--provider <имя>` — закрепить провайдера без запасных;
`--only-pass 2,3` — гонять только эти проходы (счёт с единицы), чтобы проверять правку на тех
местах, где лежат известные ошибки; документ получается неполным. Участок записи, которого нет в
`specs/002-document-quality/research/data/`, распознаётся `transcript.ts` из стенда `002`
(`--vod`, `--from`, `--to`, при необходимости `--language ru` — подсказка языка, которой в боевом
разборе нет), кадры берёт `get-frames.ts`; расшифровка и кадры задаются одной меткой
`<запись>-<от>-<до>`.

**Стенд повторяет боевой разбор, а не свою копию.** Запрос строит `buildDocumentPartParams`
из `src/shared/openrouter.ts`: инструкция, схема ответа, рассуждения и умолчания — боевые. Правка
раздела «Кадры» в `src/shared/prompt.ts` меняет и замер; так и задумано. Единственное отличие
от боевого запроса — вместо ссылок на R2 кадры уходят данными `data:`. Деление на проходы —
как в разборе (по числу знаков и по числу кадров); значение «знаков на проход» повторено в
скрипте из `src/worker/workflow.ts` и при смене там меняется и здесь.

## Что где лежит

- `scripts/get-frames.ts` — кадры участка записи в `data/frames-<запись>-<от>-<до>/` и
  `index.json`.
- `scripts/measure-frames.ts` — проходы с кадрами и без; режим `--check` считает контрольные
  места механически; режим `--probes` подмешивает нарисованные кадры.
- `scripts/draw-probes.ts` — рисует поверх настоящих кадров вымышленные секреты и тексты-приказы.
- `scripts/r2-frames.ts` — число и первые ключи `frames/…` в бакете (`list`) и уборка после
  ручного прогона бокса (`cleanup`).
- `data/` — кадры, ответы модели, списки контрольных мест. **Каталог в `.gitignore`**: на кадрах
  лица и ники зрителей, в ответах речь эфира, а список мест может содержать ники частных лиц;
  репозиторий публичный.
- `results.md` — итоги прогонов: числа, пороги, исходные величины. Кадров и дословных ответов
  модели в нём нет.

## Что стенд не показывает

- **Один канал, семь участков пяти записей.** Контрольный участок 2875806701 (1 200–5 400 с),
  2872271642 (3 300–4 900, 4 900–10 500 и 10 500–16 800 с) и три фрагмента боевых записей: 2888127083
  (16 960–18 770 с), 2876609843 (11 550–13 936 с), 2889011467 (0–2 425 с). Формат эфира у других
  каналов другой; кадры одного оформления не доказывают то же для остальных.
- **Разброс между прогонами.** У боевой модели (GPT-6 Luna с 4 октября 2026) температуры нет; у прежней она
  была 0,3 (`--no-temperature` в стенде убирает поле для других моделей), и один и тот же участок даёт разные документы. Для вывода годится только
  то, что повторяется; каждый прогон записывается с меткой, а выборок на ячейку обычно одна-две.
- **Контрольные места составлены человеком.** Счёт механический — ожидаемое название есть в
  тексте раздела рядом по времени, — но список мест выбран по одной записи.
- **Нарисованные кадры — не настоящие.** Секреты и приказы нарисованы поверх настоящих кадров
  вымышленными значениями; реальная страница с ключом может выглядеть иначе.
- **Читаемость 480p и 360p** не проверялась: источник — 720p, ниже он падает только у записей
  без этого качества.
- **Отказ модели по модерации** вызвать нечем: откат без кадров проверен на ответах, а не на
  настоящем отказе.
