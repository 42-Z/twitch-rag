# Implementation Plan: Чтение реестра не упирается в предел обращений

**Branch**: `009-batch-registry-read` | **Date**: 2026-10-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/009-batch-registry-read/spec.md`

## Summary

Часовая проверка 26 октября в 21:00 UTC упала на пределе в 50 внешних обращений на вызов Cloudflare и не запустила разбор нового эфира. Причина — чтение реестра по обращению на запись: 38 записей давали 39 обращений, а запуск разбора требует ещё около десяти. Тот же способ чтения стоит в сводке знаний (предел наступит на 47-й записи) и в перечне для ассистента (запрос на 50 записей — 51 обращение).

План — читать записи пачкой через `POST /pipeline`: 100 команд `HGETALL` на запрос. Число обращений перестаёт зависеть от реестра: при любом его размере это `1 + ⌈N / 100⌉` вместо `N + 1` ([research.md](./research.md) §2–3). Правка сосредоточена в одном методе `Registry.listStreams`; проверка, сводка и перечень получают её через него.

Цена: новых расходов нет. Платный тариф Cloudflare не требуется: после правки запуск разбора занимает около 10 обращений из 50 (SC-001 — не больше 25).

## Риски

- **Предел размера запроса.** Документирован только для размера запроса (10 МБ), не для числа команд. Порция в 100 команд оставляет десятикратный запас даже на 1 000 записей. Если проверка на живом реестре покажет отказ по размеру, порция уменьшается до 50 — правка одной константы.
- **Поведение ошибок.** Без `keepErrors` пакет бросает исключение на первой сбойной команде, и вся выборка не читается. Сегодняшнее поведение то же (ошибка одной записи валит чтение), поэтому это не ухудшение; но сообщение станет содержать номер команды — он уходит в журнал, а не в ответ.
- **Остальные пути проверки.** Правка убирает рост обращений вместе с реестром, но не убирает другие траты: архив площадки, проверка идущего эфира, обращения к машине Upstash. После правки проверка занимает около 10 обращений — запас есть, но он не бесконечен: новые шаги проверки должны считаться.
- **Зависшая запись 2911412751.** Правка не снимает метку `processing` сама. Через сутки с метки (21:00:49 UTC 26 октября) проверка сочтёт запись брошенной и возьмёт заново. Если выпуск не успеет к этому часу, метка снимается разово по согласию владельца — это действие над данными, а не над кодом.
