# Как проверить: чтение реестра одной операцией

**Дата**: 2026-10-27

Проверки ниже не требуют выпуска и не тратят денег.

## Подготовка

```sh
npm ci
```

## Автоматические проверки

```sh
npx vitest run --project logic
npx vitest run --project workers
npm run typecheck
```

**Что должно быть видно.**

- Проверка числа обращений: полное чтение реестра из 1 записи — 2 запроса к хранилищу, из 400 — 5 (1 `ZRANGE` + 4 пачки). При возврате к чтению по одной та же проверка покажет 401 и упадёт.
- Проверка совпадения: запись, прочитанная пачкой, равна записи, прочитанной по одной (поля, типы, порядок).
- Проверка пропуска: запись, удалённая между списком и чтением, в результате отсутствует, ошибки нет.
- Проверка отбора: часовая проверка на подставном реестре выбирает ту же запись, что и прежде (`tests/unit/schedule-select.test.ts` и соседние — без изменений).

## Проверка на тестовой копии Worker'а (после правки кода, до слияния)

1. Выложить копию: `npx wrangler deploy -c wrangler.dev.jsonc`.
2. Открыть страницу копии и попросить ассистента перечислить трансляции, затем посмотреть сводку знаний — обе читают реестр новым путём.
3. В журнале Worker'а (`npx wrangler tail twitch-rag-dev`) убедиться, что запросов к реестру на один вызов приходится несколько, а не по числу записей.

**Ожидаемо:** ответы те же, что на боевой странице; в журнале нет `Too many subrequests`.

## Приёмочные проверки после выпуска

Выполняются после слияния в основную ветку, в список задач не входят.

1. **Первый новый эфир.** Дождаться очередной часовой проверки с новой записью в архиве. В аналитике Cloudflare (`workersInvocationsAdaptive`, фильтр `scriptName: twitch-rag`) исход — `success`, внешних обращений меньше 25. В реестре (`stream:<id>`, поле `status`) — `processing`, затем `ready`.
2. **Зависшая запись 2911412751.** Если к моменту выпуска она ещё в `processing`, часовая проверка возьмёт её заново после суток с метки (21:00:49 UTC 26 октября), потому что брошенная запись считается свободной. Отдельного действия над данными не требуется, если проверка сработала в срок; иначе метка снимается разово по согласию владельца.
3. **Сводка знаний на выросшем реестре.** После того как записей станет больше 47, страница обязана открываться без ошибки сводки.
