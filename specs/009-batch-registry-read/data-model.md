# Модель данных: чтение реестра одной операцией

**Дата**: 2026-10-27

Форма записей реестра не меняется. Ниже — то, что относится к новому чтению.

## Сущности

### Запись трансляции в реестре (`stream:<streamId>`)

Хеш в Upstash Redis, поля прежние (`src/shared/registry.ts:36-80`): `vodId`, `status`, `title`, `docTitle`, `url`, `publishedAt`, `publishedAtUnix`, `durationSeconds`, `categories`, `sectionCount`, `chunkCount`, `speechSeconds`, `docPath`, `source`, `reason`, `attempts`, `costUsd`, `processedAt`, `nameAttempts`, `part`, `partCount`, `partStartSeconds`.

**Изменений нет.** Чтение пачкой возвращает те же значения в том же приведении к типам (`toStreamRecord`, `asString`, `asNumber`, `asChapters`).

### Список известных записей (`streams:index`)

Упорядоченное множество идентификаторов с весом `publishedAtUnix`. Читается одним `ZRANGE … REV`; порядок — новые первыми. **Изменений нет.**

### Пачка чтения

Не хранится; существует только в одном вызове.

| Свойство | Значение |
|---|---|
| Состав | от 1 до 100 команд `HGETALL` на ключи `stream:<id>` |
| Откуда идентификаторы | из `streams:index` |
| Результат | массив значений в порядке команд |
| Запись отсутствует | `null` → пропускается |
| Ошибка команды | исключение по номеру команды → `upstreamError("реестр", …)` |

## Правила

- **Порядок.** Записи идут в порядке, в каком их вернул `ZRANGE … REV`; пачки добавляются по возрастанию номера и общий порядок не нарушают.
- **Пропуск.** Запись, удалённая между `ZRANGE` и чтением, в результат не попадает и ошибки не вызывает.
- **Приведение.** Значения, похожие на JSON, клиент разбирает сам; правила приведения прежние.
- **Порция.** 100 команд на запрос; число запросов — `1 + ⌈N / 100⌉`.

## Что не меняется

- Ключи и поля реестра.
- Производные виды: карта `streamId → запись` для отбора проверки, подсчёт сводки знаний, перечень для ассистента.
- Пути записи: `putStream`, `patchStream`, `claimForIngest`, `recordCheck`.
