## Phase 3: User Story 1 - Новый эфир берётся в разбор при любом размере реестра (Priority: P1) 🎯 MVP

**Goal**: часовая проверка читает записи пачками и укладывается в 50 внешних обращений на вызов при любом размере реестра; новый эфир уходит в разбор.

**Independent Test**: на подставном реестре из 40 записей часовая проверка с новым эфиром в архиве запускает разбор, а число запросов к реестру — 2 (1 `ZRANGE` + 1 пачка), не 41.

### Implementation for User Story 1

- [x] T004 [US1] Переписать `Registry.listStreams` в `src/shared/registry.ts` на пачки: константа `READ_BATCH = 100` (порция команд на запрос), `ZRANGE … REV` за идентификаторами, затем `redis.pipeline()` с `HGETALL` на каждую запись порциями по 100 и `exec()`; отсутствующие записи (`null`) пропускать; ошибку `exec()` оборачивать в `upstreamError("реестр", …)`; порядок записей — как у `ZRANGE … REV`
- [x] T005 [US1] Убрать из `Registry` метод `knownStreamIds`, если после T006 у него не осталось применений в `src/` и `tests/` (конституция, IV: мёртвый код удаляется в той же задаче). Убран вместе с двумя проверками самого метода: приведение цифрового идентификатора к строке перенесено в проверку чтения пачкой
- [x] T006 [US1] В `runScheduledCheck` (`src/worker/schedule.ts`) заменить `knownStreamIds()` + чтение `getStream` в цикле на один `listStreams()` и карту `streamId → запись` из него; поведение отбора, пропуска обрывков и перевода исчерпавших попытки не менять
- [x] T007 [US1] Проверить, что `npx vitest run --project logic` проходит по `tests/unit/registry-batch.test.ts` и существующим проверкам отбора (`tests/unit/schedule-select.test.ts`, `schedule-skip.test.ts`, `schedule-part-failure.test.ts`) — без правок их ожиданий
- [x] T008 [US1] Добавить в `tests/worker/worker.test.ts` проверку часовой проверки на подставном реестре из 40 записей с новым эфиром в архиве: разбор запущен, все 40 записей пришли одной пачкой, обращений к реестру за вызов — 11 (замер), из них на чтение реестра 3 вместо 41

## Phase 4: User Story 2 - Страница и ассистент получают сводку и перечень при любом размере реестра (Priority: P2)

**Goal**: сводка знаний и перечень трансляций для ассистента читают реестр тем же путём и не зависят от его размера.

**Independent Test**: сводка знаний и перечень на 50 записей при пустом кэше тратят столько же обращений к реестру, сколько при 1 записи.
