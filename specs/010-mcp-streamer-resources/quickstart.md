# Как проверить: сведения о стримере как ресурс MCP

**Дата**: 2026-11-19

Проверки ниже не требуют платных прогонов и не запускают разбор.

## Подготовка

```sh
npm ci
```

## Автоматические проверки

```sh
npx vitest run --project logic
npx vitest run --project workers
npm run typecheck
npm run build
```

**Что должно быть видно.**

- **Перечень.** Поле для ассистента заполнено — `resources/list` содержит ровно один ресурс `streamer://info` с названием и описанием; поле пустое — список пуст.
- **Чтение.** `resources/read` отдаёт сохранённый текст знак в знак (без краевых пробелов), без обёртки инструкции; после правки поля следующее чтение отдаёт новый текст.
- **Пустое поле.** Перечня нет; чтение отвечает «ресурс не найден»; текст поля для разбора не подставляется.
- **Независимость полей.** Правка поля для разбора не меняет ресурс; правка поля для ассистента не меняет инструкцию разбора — хеш инструкции в `tests/unit/prompt.test.ts` прежний.
- **Страница.** В разделе управления два поля с разными названиями и пояснениями; раздел MCP показывает текущий текст, при пустом поле — сообщение, что ресурса нет, и где его заполнить.
- **Типы и сборка.** Проходят без ошибок.

## Проверка на тестовой копии Worker'а (до слияния)

Копия описана в `CLAUDE.md`, «Проверка на тестовой копии воркера». Данные у неё общие с сайтом, поэтому текст поля меняется и на сайте.

1. Выложить копию: `npx wrangler deploy -c wrangler.dev.jsonc`.
2. Открыть страницу копии, ввести токен владельца и заполнить поле для ассистента текстом из [streamer-info.md](./streamer-info.md).
3. Подключить MCP-клиент к `<адрес копии>/mcp` (`npx @modelcontextprotocol/inspector`) и запросить перечень ресурсов, затем прочитать `streamer://info`.
4. Очистить поле и повторить перечень и чтение.

**Ожидаемо:** после заполнения в перечне один ресурс, чтение отдаёт введённый текст; после очистки перечня нет, чтение — «ресурс не найден»; инструменты `search_knowledge`, `knowledge_stats`, `list_streams` отвечают как прежде. Страница копии показывает тот же текст.

После проверки вернуть полю настоящее значение и удалить копию: `npx wrangler delete -c wrangler.dev.jsonc`.

## Проверки после выпуска

Выполняются после слияния в основную ветку; в список задач не входят.

1. Сохранить текст из [streamer-info.md](./streamer-info.md) в поле для ассистента на боевой странице.
2. В разделе MCP виден этот текст; настоящий MCP-клиент видит ресурс в перечне и читает его без токена.
3. После очистки поля ресурс исчезает из перечня, а чтение отвечает отказом.
