# Feature Specification: Общая информация о стримере для ассистента как ресурс MCP

**Feature Branch**: `010-mcp-streamer-resources`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "Давай добавим возможность задавать ресурсы в MCP с общей информацией о стримере"

**Уточнения (2026-11-19)**: поле «О стримере» занято нейросетью, которая форматирует распознанный текст; для агента, вызывающего MCP, нужно отдельное поле, и эти поля надо разделить. Если информация не задана, ресурсов в MCP нет — вызвать их нельзя, и ответа быть не может. Ресурс доступен всем. Страница должна показывать актуальное содержание.

**Связь с предыдущей работой**: продолжает `001-stream-archive-rag` (публичный MCP-сервер с инструментами) и `002-document-quality` (поле «О стримере» для разбора, FR-014…FR-019). Поле для разбора и сам разбор не меняются: добавляется отдельное поле для ассистента и его ресурс.

## Зачем это нужно

Сейчас у сервиса одно поле «О стримере». Оно рабочее: по нему нейросеть, составляющая документ, узнаёт, как на самом деле пишутся имена, кто постоянные собеседники и что значат свои словечки. Текст этого поля уходит в системную инструкцию каждого прохода, и менять его — значит менять разбор.

Ассистенту, который подключается к серверу по MCP, нужно другое: общая информация о стримере и канале, которую он может рассказать человеку. Это не инструкция для форматирования и не список исправлений распознавания. Если оставить одно поле на двоих, правка для ассистента меняла бы разбор, а правка для разбора — ответы ассистента. Поэтому поля разделяются: у разбора своё, у ассистента своё.

Сейчас у ассистента нет и такого: сервер отдаёт три инструмента — поиск, перечень и сводку, — но ни одного источника об этом канале. В MCP для данных, которые нужны как контекст, есть отдельный вид — ресурсы. Ресурс — это адресуемые данные, которые клиент получает по своему усмотрению, не дожидаясь, пока модель решит вызвать инструмент: клиент может показать их человеку в списке, подключить к разговору или подставить в контекст. Общая информация о стримере — ровно такой случай.

Ресурс собирается из нового поля, которое владелец заполняет на странице управления. Пока поле пустое, ресурса нет вовсе: в перечне его не будет, и вызвать его нельзя — сервер не отвечает пустотой и не подставляет сведения из поля для разбора.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Клиент ассистента получает общую информацию о стримере (Priority: P1)

Клиент ассистента, подключённый к серверу, обнаруживает в перечне ресурсов запись с общей информацией о стримере и читает её — по выбору человека или по своим правилам. Полученный текст рассказывает, кто такой стример и о чём канал. Ассистент может ответить на вопросы о канале и использовать эти сведения как контекст, не вызывая инструменты.

**Why this priority**: Ради этого ресурс и делается. Без него у ассистента по-прежнему нет ни одного источника об этом канале, кроме самих пересказов.

**Independent Test**: Достаточно заполненного поля для ассистента и клиента, поддерживающего ресурсы: клиент получает перечень, находит в нём ресурс, читает его и получает сохранённый текст — без вызова инструментов.

**Acceptance Scenarios**:

1. **Given** поле для ассистента заполнено, **When** клиент запрашивает перечень ресурсов, **Then** в перечне есть ресурс с общей информацией о стримере — с понятным человеку названием, описанием и постоянным адресом.
2. **Given** клиент прочитал ресурс, **When** он сравнивает полученный текст с сохранённым, **Then** тексты совпадают знак в знак (без ведущих и замыкающих пробелов), и содержимое помечено как обычный текст.
3. **Given** владелец сохранил другой текст, **When** клиент читает ресурс снова, **Then** он получает новый текст — без перезапуска сервера и без переподключения.

---

### User Story 2 - Владелец заполняет отдельное поле и видит, что получает ассистент (Priority: P2)

На странице управления два разных поля: прежнее — для разбора, новое — для ассистента. У каждого своё название и пояснение, зачем оно нужно. Владелец правит новое поле, не рискуя изменить разбор, и на странице видит текущее содержание того, что получает ассистент.

**Why this priority**: Разделение полей — суть работы. Без отдельного поля владелец правил бы не тот текст; без показа текущего содержания он не может убедиться, что ассистент получает именно то, что нужно.

**Independent Test**: Достаточно страницы в браузере: два поля с различимыми названиями и пояснениями; сохранение одного не меняет другое; раздел MCP показывает текущее содержание ресурса.

**Acceptance Scenarios**:

1. **Given** канал подключён, **When** владелец открывает раздел управления, **Then** на странице два поля — для разбора и для ассистента — с названиями и пояснениями, которые не путают их между собой.
2. **Given** владелец сохранил новое поле, **When** составляется инструкция разбора, **Then** в ней прежний текст поля для разбора, а ресурс отдаёт новый текст.
3. **Given** владелец сохранил поле для разбора, **When** клиент читает ресурс, **Then** текст ресурса не изменился.
4. **Given** поле для ассистента заполнено, **When** владелец открывает раздел MCP, **Then** раздел показывает текущее содержание ресурса — тот самый текст, который получает ассистент, — и где он правится.
5. **Given** поле для ассистента пусто, **When** владелец открывает раздел MCP, **Then** раздел говорит, что ресурса нет, и где его заполнить.

---

### Edge Cases

- **Поле для ассистента пустое, поле для разбора заполнено.** Ресурса нет: поле для разбора не подставляется как запасной источник. Ассистент получает только инструменты.
- **Поле для разбора пустое, поле для ассистента заполнено.** Ресурс есть; разбор идёт без сведений, как и раньше.
- **Оба поля заполнены по-разному.** Каждый потребитель получает своё: разбор — текст для разбора, ассистент — общую информацию.
- **Пустое поле.** Пустая строка и строка из одних пробелов означают «не задано»: ресурса в перечне нет, чтение по его адресу отвечает «ресурс не найден» по правилам протокола. Пустой текст и заглушка не возвращаются.
- **Канал не подключён.** Записи канала нет — нет и полей; ресурс не предлагается, остальные инструменты работают как прежде.
- **Хранилище недоступно.** Запрос, которому нужны сведения, завершается явной ошибкой; пустой перечень или пустой текст вместо ошибки не подставляются.
- **Владелец очистил поле при подключённом клиенте.** Следующее чтение отвечает «ресурс не найден», следующий перечень ресурса не содержит. Это не сбой клиента, а изменение данных.
- **Очень длинный текст.** Сведения возвращаются целиком в пределах предела поля; обрезания и пересказа нет.
- **Текст с разметкой.** Содержимое отдаётся как текст, без толкования и без добавления обёртки инструкции: ресурс — данные, а не правила.
- **Клиент без поддержки ресурсов.** Он получает те же инструменты и те же ответы, что и раньше; отсутствие работы с ресурсами не мешает поиску.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Сервис MUST хранить общую информацию о стримере для ассистента отдельно от сведений для разбора: это два независимых значения, и правка одного MUST NOT менять другое.
- **FR-002**: Страница управления MUST содержать отдельное поле для общей информации о стримере с названием и пояснением, отличающим его от поля для разбора; владелец MUST понимать, какое поле куда идёт.
- **FR-003**: Сервер MUST объявлять клиенту поддержку ресурсов и отдавать в перечне ресурс с общей информацией о стримере, когда поле для ассистента заполнено.
- **FR-004**: У ресурса MUST быть постоянный адрес, не меняющийся при правке текста; название и описание MUST быть понятны человеку, читающему перечень; содержимое — обычный текст.
- **FR-005**: Чтение ресурса MUST возвращать текст поля для ассистента без пересказа, без обрезания и без обёртки, в которую сведения попадают при составлении документа. Ведущие и замыкающие пробелы содержимым не считаются.
- **FR-006**: Содержимое MUST быть текущим на момент каждого обращения: сохранённая правка видна следующему чтению без перезапуска сервера и без переподключения клиента; перечень отражает состояние на момент запроса.
- **FR-007**: Если поле для ассистента пустое (пустая строка или одни пробелы), ресурса MUST NOT быть: в перечне его нет, чтение по его адресу отвечает «ресурс не найден» по правилам протокола. Пустой текст, заглушка или сведения из поля для разбора MUST NOT возвращаться.
- **FR-008**: Поле для разбора MUST NOT использоваться как запасной источник для ресурса, а поле для ассистента MUST NOT попадать в инструкцию разбора.
- **FR-009**: Разбор документов MUST остаться прежним: при неизменном поле для разбора инструкция совпадает с прежней байт в байт, и существующие проверки проходят без правок ожиданий.
- **FR-010**: Инструменты ассистента и их ответы MUST остаться прежними; ресурс MUST NOT подменять их и не дублировать их ответы.
- **FR-011**: Ресурс MUST быть доступен всем, кто подключается к публичному MCP-серверу; аутентификация для него MUST NOT вводиться.
- **FR-012**: Ресурс MUST быть только для чтения: через MCP общая информация не меняется; правка остаётся на странице управления.
- **FR-013**: Раздел MCP на странице MUST показывать текущее содержание ресурса — тот текст, который получает ассистент, — и где он правится; при пустом поле он MUST говорить, что ресурса нет, и где его заполнить.
- **FR-014**: Поле для ассистента MUST принимать текст до того же предела, что и поле для разбора (20 000 знаков), и при превышении отказывать человеческим текстом, не сохраняя обрезанное.

### Key Entities

- **Сведения о стримере для разбора**: существующее поле, свободный текст до 20 000 знаков; уходит в инструкцию разбора; форма и назначение не меняются.
- **Общая информация о стримере для ассистента**: новое поле, свободный текст до 20 000 знаков; пустая строка и отсутствие поля равнозначны «не задано»; уходит только в ресурс MCP.
- **Ресурс MCP**: адресуемый объект только для чтения — постоянный адрес, название, описание и текстовое содержимое, собранное из нового поля. Новых данных не хранит.
- **Канал**: отслеживаемый канал в реестре; хранит оба текста.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Клиент, поддерживающий ресурсы, обнаруживает ресурс в перечне и получает текст одним чтением, без вызова инструментов; полученный текст совпадает с сохранённым полем для ассистента знак в знак (без ведущих и замыкающих пробелов).
- **SC-002**: Если поле для ассистента пустое, а поле для разбора заполнено, ресурса нет в перечне, а чтение по его адресу отвечает «ресурс не найден»; пустой или подставной текст не возвращается.
- **SC-003**: Правка поля для разбора не меняет текст ресурса; правка поля для ассистента не меняет инструкцию разбора. Проверяется сравнением до и после.
- **SC-004**: После сохранения нового текста следующее чтение отдаёт новый текст — без перезапуска сервера и без переподключения клиента.
- **SC-005**: Раздел MCP на странице показывает текущее содержание ресурса, а при пустом поле говорит, что ресурса нет. Проверяется разметкой страницы.
- **SC-006**: Прежние инструменты и разбор документов отвечают так же, как до изменения: их ответы не изменились, прежние проверки проходят без правок ожиданий.
- **SC-007**: Любой клиент читает ресурс без авторизации: сервер остаётся публичным.

## Assumptions

- **Новое поле живёт в записи канала рядом с прежним.** Отдельного хранилища не заводится.
- **Предел длины — как у поля для разбора (20 000 знаков).** Двух разных пределов у двух полей не появляется.
- **Одно поле — один ресурс.** Поле — один текст, и делить его на несколько ресурсов не на что.
- **Новое поле начинается пустым.** Автоматического копирования из поля для разбора нет: назначение у текстов разное, и копия разошлась бы с оригиналом при первой правке.
- **Прежнее поле и его назначение не меняются.** Меняется только страница: у поля появляется пояснение, что оно для разбора. Хранимый текст и его место в инструкции — прежние.
- **Ресурс публичен, как и сервер.** Новый текст пишется для всех, кто подключается; сведений, которые нельзя показывать, в нём быть не должно.
- **Уведомлений об изменениях нет.** Сервер работает без состояния: клиент видит правку при следующем обращении, а не получает сообщение об изменении.
- **Раздел MCP и раздел управления обновляются в этой же работе.** Иначе владелец не узнает о новом поле и не увидит, что получает ассистент.
- **Клиент, держащий перечень с момента подключения, увидит ресурс при следующем запросе перечня.** Проталкивать изменение сервер не может — это следствие работы без состояния, а не отдельная задача.
- **Приёмочные проверки после выпуска** (живой клиент MCP, видимость ресурса в его списке) в список задач не входят: они про то, что выпущенное работает, и делаются после выпуска.
