# Модель данных: качество документа, сведения о стримере, имя от содержания

**Дата**: 2026-09-17 | **Спецификация**: [spec.md](./spec.md) | **План**: [plan.md](./plan.md)

Разделение хранилищ из 001 не меняется: R2 — временное аудио разбора, Blob — документы,
Vector — разделы для поиска, Redis — реестр и настройки. Новое появляется в Redis
(сведения о стримере), в реестре трансляции (имя документа) и в тексте документа.

## 1. Upstash Redis

### `channel` (hash) — дополняется одним полем

| Поле | Тип | Правила |
|------|-----|---------|
| `twitchUserId`, `login`, `displayName`, `watchFrom`, `addedAt`, `lastCheckedAt`, `lastCheckError` | как в 001 | без изменений |
| `streamerInfo` | string | **новое.** Сведения о стримере: кто это, о чём канал, кто постоянные собеседники, свои словечки. Одно поле свободного текста, правится владельцем. Пустая строка и отсутствие поля равнозначны «не заполнено» |

**Почему в `channel`, а не отдельным ключом**: сведения относятся к единственному
отслеживаемому каналу и меняются вместе с ним; отдельный ключ дал бы вторую запись,
которую надо держать согласованной, ничего не добавив.

**Оговорка о видимости.** База реестра читается страницей по read-only токену, который
лежит в сборке интерфейса, то есть фактически публичен. Значит `streamerInfo` технически
читаем любым, кто открыл страницу, хотя секция в интерфейсе и скрыта до предъявления
токена владельца (FR-020). Поле предназначено для описания канала, а не для секретов;
если владельцу понадобится писать туда сокровенное, потребуется отдельное хранилище —
это осознанное ограничение, а не недосмотр.

### `stream:<vodId>` (hash) — дополняется одним полем

| Поле | Тип | Правила |
|------|-----|---------|
| `vodId`, `status`, `title`, `url`, `publishedAt`, `publishedAtUnix`, `durationSeconds`, `language`, `categories`, `sectionCount`, `chunkCount`, `speechSeconds`, `docPath`, `source`, `reason`, `attempts`, `costUsd`, `processedAt` | как в 001 | без изменений |
| `docTitle` | string | **новое.** Имя документа, выработанное по содержанию эфира. Заполняется на шаге составления имени; у разобранного документа оно есть всегда |

**Правила**:

- `title` (заголовок с площадки) остаётся служебным полем реестра и нигде не
  показывается: ни в интерфейсе, ни в выдаче знаний, ни в документе (FR-027).
- `docTitle` — единственное имя документа. Оно же попадает в шапку документа, в список
  разобранного, в выдачу знаний и в перечень трансляций для ассистента (FR-025).
- Запись, разобранная до этой задачи, поля `docTitle` не имеет. Пока она не перебрана
  заново, везде, где показывается имя, действует порядок: `docTitle`, иначе — прежнее
  `title`. Это временное состояние, а не правило: повторный разбор его снимает.
- Повторный разбор заменяет `docTitle` вместе с остальными полями разбора.

## 2. Upstash Blob: документы

Путь прежний — `streams/<vodId>.md`. Меняется шапка: вместо заголовка площадки в ней
имя документа, выработанное по содержанию.

```
# Как Мafаня разыграл зрителей треком на час

**Эфир**: 2026-09-16 · **Длительность**: 3 ч 49 мин · **Категории**: Just Chatting
```

Разделы остаются размеченным текстом со временем и категорией в строке заголовка —
как в 001, потому что время раздела вернулось в требования:

```
## Выборы и «Новые люди» [1:12:30 — 1:18:40 · Just Chatting]
```

## 3. Upstash Vector: куски разделов

Идентификатор, размеры кусков, контекстная строка и правила нарезки — как в 001.
Метаданные меняются в одном поле:

| Поле | Тип | Назначение |
|------|-----|-----------|
| `title` | string | **теперь имя документа** (`docTitle`), а не заголовок площадки (FR-027) |
| `vodId`, `publishedAt`, `publishedAtUnix`, `category`, `sectionIndex`, `sectionTitle`, `sectionText`, `startSeconds`, `endSeconds`, `url`, `language` | как в 001 | без изменений: время начала и конца раздела, категория на момент разговора и ссылка с таймкодом остаются |

**Правила**:

- `startSeconds < endSeconds`, оба в пределах длительности эфира — как прежде.
- Покрытие эфира по времени проверяется на шаге приведения разделов: разрыв больше
  порога означает пропущенный кусок и попадает в реестр причиной (FR-040).
- Куски, записанные до этой задачи, несут в `title` заголовок площадки. Выдача читает
  это поле как имя документа, поэтому у неперебранных трансляций в выдаче будет
  заголовок площадки — до повторного разбора.

## 4. Cloudflare R2: временные файлы разбора

Без изменений: `audio/<vodId>/…` живёт до распознавания куска, `transcript/<vodId>/…` —
до конца разбора. Уборка по прежним правилам.

## 5. Состояние разбора (внутри Workflow)

Добавляется одна структура:

| Структура | Поля | Живёт |
|-----------|------|-------|
| `DocumentName` | `name` — имя документа, выработанное отдельным запросом | от выработки имени до записи в реестр |

Остальные структуры прежние: входные данные инстанса, `ChunkTranscript`, `Transcript`,
`DocumentPart`, `Section` (у раздела снова есть `startSeconds`, `endSeconds`, `category`).

**Порядок шагов разбора** (меняется в двух местах):

1. распознавание кусков и уборка аудио — как прежде;
2. склейка расшифровки — как прежде;
3. проходы составления документа по строгой схеме — прежний размер участка;
4. приведение разделов, категории по времени, проверка покрытия — как прежде;
5. индексация кусков — как прежде;
6. **выработка имени документа** — отдельный шаг после сборки разделов;
7. сохранение документа с именем в шапке и отметка `ready` с `docTitle`.
