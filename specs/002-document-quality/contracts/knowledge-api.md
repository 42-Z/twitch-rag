# Контракты: что меняется против `001-stream-archive-rag`

**Дата**: 2026-09-17 | **Спецификация**: [../spec.md](../spec.md)

Контракты 001 остаются в силе. Ниже — только изменения: одно поле в выдаче знаний и два
новых управляющих действия. Формат описания и коды ошибок — те же, что в
`001-stream-archive-rag/contracts/knowledge-api.md`.

## POST /api/knowledge/search — меняется одно поле в ответе

Поле `stream.title` теперь несёт **имя документа**, выработанное по содержанию эфира
(FR-025), а не заголовок трансляции с площадки. Заголовок площадки в выдаче не
появляется вовсе (FR-027).

```json
{
  "found": true,
  "documents": [
    {
      "id": "2875806701:12",
      "topic": "Выборы и «Новые люди»",
      "text": "Полный текст раздела…",
      "score": 0.82,
      "category": "Just Chatting",
      "stream": {
        "vodId": "2875806701",
        "title": "Как Мафаня разыграл зрителей треком на час",
        "publishedAt": "2026-09-16T16:54:29Z",
        "url": "https://www.twitch.tv/videos/2875806701?t=1h12m30s"
      },
      "startSeconds": 4350,
      "endSeconds": 4720
    }
  ],
  "stats": { "returned": 1, "latencyMs": 240 }
}
```

**Правила**

- Имя то же самое, что в шапке документа и в списке разобранного; расхождение между
  тремя местами — дефект (SC-012).
- У трансляции, разобранной до этой задачи и ещё не перебранной, в `title` будет
  заголовок площадки: имена вырабатываются при разборе, задним числом их не появляется.
- Время раздела, категория и ссылка с таймкодом — без изменений против 001.

## PUT /api/streamer — новое, управляющее

Сведения о стримере (FR-014, FR-015). Требует токена владельца в заголовке
`Authorization: Bearer <APP_ADMIN_TOKEN>`, как остальные управляющие действия.

Запрос: `{ "info": "5opka — Михаил, стримит истории из жизни и разборки с чатом. Постоянные собеседники: Соня, Влад, Мафаня." }`

Ответ 200: `{ "saved": true }`

**Правила**

- `info` — свободный текст. Пустая строка сохраняется и означает «сведений нет»:
  разбор идёт так же, как если бы поле никогда не заполнялось (FR-016).
- Содержимое не проверяется и не истолковывается: что владелец написал, то и уходит в
  системную инструкцию (FR-015).
- Изменение действует на последующие разборы; на уже разобранное влияет только
  повторный разбор (FR-017).
- Чтение поля отдельного запроса не требует: страница читает `channel` из реестра
  напрямую, как и остальные настройки канала.

## POST /api/streams/:vodId/reparse — новое, управляющее

Запуск разбора заново (FR-028). Требует токена владельца.

Ответ 202: `{ "vodId": "2875806701", "status": "processing" }`

Ошибки:

| Случай | Код | Тело |
|--------|-----|------|
| Разбор этой трансляции уже идёт | 409 | `{ "error": "reparse_running", "message": "Разбор этой трансляции уже идёт." }` |
| Трансляция неизвестна реестру | 404 | `{ "error": "not_found", "message": "Такой трансляции в реестре нет." }` |
| Запись больше недоступна у площадки | 202, затем `skipped` | как при первом разборе: причина попадает в реестр |

**Правила**

- Повторный разбор равноценен первому по работе и затратам: запись скачивается и
  распознаётся заново (FR-035).
- Знания трансляции заменяются целиком: разделы прежнего разбора удаляются до записи
  новых, смеси в выдаче не бывает (FR-031).
- Неудача повтора не лишает трансляцию прежних знаний (FR-032).
- Автоматика повторный разбор не запускает никогда (FR-029).

## MCP-сервер — меняются формулировки инструментов

Инструменты, их схемы и формат ответа те же, что в
`001-stream-archive-rag/contracts/mcp-server.md`. Меняется то, как называется трансляция
в ответе: в перечне разобранного и в выдаче поиска стоит имя документа, а не заголовок с
площадки. Описания инструментов, где сказано «название трансляции», переписываются на
«имя документа», чтобы ассистент не искал то, чего в выдаче нет.
